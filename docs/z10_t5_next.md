## 3. 最小对比实验（T5第1轮已启动）

前置条件：原三轮与输入/报告已归档；用户后续明确要求继续修改。不能用
`ResumeId` 改名把第四次实现当成第三轮恢复，也不能直接复跑覆盖旧 run。

1. 先备份第三轮完整实现目录/检查点，保存每个成员的 SHA256；当前阶段 ZIP
   主要保存源码和报告，不应当作实现 DCP 的替代品。
2. 创建独立 T5 日志和输入清单，复核第三轮 `synth_1` 完成且源码一致。
3. 只改变功耗优化因素：在**最后一次设置实现属性之后、launch_runs 之前**，
   将 `STEPS.POWER_OPT_DESIGN.IS_ENABLED` 和
   `STEPS.POST_PLACE_POWER_OPT_DESIGN.IS_ENABLED` 同时设为 `false`。
   当前 `run_sentinel_v2.tcl` 会强制把两项写为 `true`，因此不能仅在调用它
   之前设一次开关；应增加明确的可记录参数并冻结新的构建脚本。
4. 保留时钟、RTL、布局策略和其他属性，复用已完成综合，仅重跑实现。
   这是新的完整实现，仍需计次；关闭功耗优化的收益目前未经实测。
5. 审查 RX/CPU/DSP 三域、全局 WNS ≥ +1 ns、WHS ≥0，以及 CDC/DRC/I/O。
   若没有达标，记录差值；不立即叠加 Pblock、RTL 改写和换策略。
6. 若证据指向 ADI 计数器结构，再在**自有覆盖层**做局部等价实验。
   必须保持计数窗口、33 位溢出/饱和、捕获握手及复位行为；不能在反馈计数器
   任意加一级使能寄存器。禁止修改 `third_party/` 或其原始许可。

### 结果出来后的最短决策路径

1. 确认 `logs/T5_v2_impl_only_r1_exit.txt` 为0，且最终布线报告确实关闭两步功耗优化；
   如进程失败先核对日志和冻结输入，不覆写历史记录。
2. 比较全局及 RX/CPU/DSP 三域 WNS、WHS、LUT/BRAM，并检查新最差路径。
   目标仍为全局 WNS≥+1.0 ns、WHS≥0；不以某一个时钟域改善代替整机达标。
3. 构建结束后运行独立的 DRC、CDC、I/O、例外及总线偏斜审计。
   这些检查和输入/位流/HWH哈希全部通过，才可讨论 v2 上板；
   `summarize_z10_audit.py` 本身不签发上板收据。
4. 如 +1 ns 仍未达到，按实际改善幅度记录 T5 结果，继续在已验收 v1d
   上推进 PS/UI/演示功能；不要为了等待 v2 而暂停不依赖新位流的开发。

第三轮冻结输入的原始字节已保存在 `report/results/z10_checkpoint_clock_root_r1.zip`。
此后仅构建控制脚本发生预期修改，因此不应再把当前脚本强行校验为第三轮输入；
应对比归档里的旧脚本并为 T5 生成新清单。HDL、封装 IP 和旧位流保持不变。

原 T5 的“统一 100 MHz AXI 域”必须指**同一个实际时钟源**，不是频率数值相等。
CPU FCLK 与外部 50 MHz MMCM 产生的 DSP 时钟没有公共主时钟，不能因两者
都是 100 MHz 就删掉 CDC。移除转换器须先重新划分寄存器/处理边界并验证
多位配置握手、快照一致性、读回和复位，属于后续独立结构修改。

## T5 第1轮实测结论（2026-11-03）

T5 实现进程退出码为1，是构建脚本按 `WNS >= +1.0 ns` 门禁拒绝签发收据，
不是布线中断。输入清单和构建日志均确认两步功耗优化为 Off，复用了综合。
最终全局 WNS/WHS 为 **+0.210/+0.030 ns**；相比第三轮 WNS 提升
0.184 ns，但离目标仍差 **0.790 ns**。LUT 37,982/53,200（约71.40%）、
FF 54,244、BRAM 92、DSP 79。独立审计自动门禁仅 setup 余量失败；
CDC Critical 仍为 110/4/26，板外 I/O 约束仍须复核，不能据此上板。

最差 setup 已移至 100 MHz `clk_fpga_0` 域：`sys_rstgen` 的
`ACTIVE_LOW_PR_OUT_DFF[0]` 到 `axi_ad9361_adc_dma` 的 `up_rdata_d_reg[21]`，
高扇出复位网 298 个负载，走线延迟 8.813 ns（数据路径的94.79%）。
这说明原RX路径不再是全局最差，但没有完成整机收敛；下一次若研究
复位分配，必须先保护既有复位/CDC语义，不能仅靠加任意流水寄存器。

软件侧在等待实现期间修复 Y3 的 CFAR 合同版本：采用
`C.VERSION_VALUE = 0x43460002`，与 `cfar_core_x5` 所用 `cfar_x1_regs`
和 `CfarX1` 驱动一致。69项相关测试通过；全套434项PC测试使用
`pytest -s` 通过。Windows 环境下 pytest 默认输出捕获偶发使Tcl
策略测试无法读取 `init.tcl`/写stdout；分开运行的430+4项也通过。
这些测试不代表Y3硬件或喇叭验收。

证据：`board/measurements/t5_result_r1.json`、
`board/measurements/z10_v2_audit_t5_r1.json` 及各自的 `.sha256`，
实现/审计日志在 `logs/T5_v2_impl_only_r1.log` 和
`logs/Z10_v2_audit_t5_r1.log`。**下一步以已验收v1d继续PS/UI功能，
Y3优先评估I2S最小PL + PS软件解调降级；v2仍需独立签核和重测才可上板。**
