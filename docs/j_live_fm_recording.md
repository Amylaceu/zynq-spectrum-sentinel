# 现场广播录制进展

用户要求在现场正常收听广播的过程中录制，再当场播放刚刚听到的内容。最终交互定义见 `runbook/J_live.md`。目前完成短录制原型和本轮录音播放器，主上位机内的录制、停止、回放、返回直播按钮尚未接入。

## 实测

| 测试 | 范围 | 结果 |
|---|---|---|
| r1 | 独立约5秒录制，采样期间拆出RX1 | ADC FIFO溢出，FAIL；没有输出可播放文件 |
| r2 | 完整ADC缓冲复制到RAM，停止后拆通道和解调 | 有限录制通过，输出约5.167秒WAV；不属于边听边录 |
| r3 | 既有FM质量门控和板载喇叭播放期间同步记录 | 19块、19922944个采样时刻，约5.188秒IQ生成5.167秒WAV；未观察到ADC FIFO溢出，播放端下溢为0 |

r3在开始录制前和完成录制后各继续播放约5秒。录制期间19个检查点均检查板载音频处于播放且未被质量门控静音。退出后独立检查GPIO/SRC/audio均为0。播放窗口只接收本次请求生成并通过摘要校验的音频，不提供历史文件选择入口。

录音来自同一时段RX1 IQ的软件FM解调，不是PL实际播放PCM逐样本读回。没有拼接离散快照间隙或填入历史声音；缺少嵌入ADC的绝对序号，短测未观察到溢出不等于证明任意时长的连续性。没有重建位流、训练模型或更改第三方代码。

用户先前给出的“回放清楚，能对应刚才的广播内容”答复随后被“我说错了，你把上位机给我打开”撤回。因此听音确认仍为 **PENDING**，不能把数值检查或窗口打开当作听音通过。对应记录为 `j_live_fm_record_r3/human_feedback.json`。

## 文件与入口

- 板端原型：`board/scripts/run_j_live_fm_record.py`。
- 本机执行：`tools/j_live_fm_record.py`，支持 `--listen-during-recording` 和 `--show-player`；凭据通过标准输入，不落盘。每次必须确认接线并停止其他RF所有者。r1–r3均已使用，不得覆盖或自行追加第四轮。
- 本轮解调与来源检查：`tools/current_fm_audio.py`。
- 本轮播放器：`tools/host/sentinel_host/current_audio.py`。
- 数据：`board/measurements/j_live_fm_record_r1/`、`r2/`、`r3/`，含JSON、SHA256、原始ADC数据及生成的WAV。原始大文件仅留本机，跨设备交接时随快照携带。

当前主界面仍使用 `tools/host/product.py`。此次用户要求打开主界面后，独立录音播放器已关闭，既有i2_r2后台服务已启动，PC主界面已连接。主界面没有因为本原型而自动获得录音按钮；应在后续集成中保持同一接收会话、明确录制状态，并在回放时静音直播。
