## 1. 现有天线与 FMCOMMS3 接口

| 编号 | 天线 | 频段 | 特点 |
|---|---|---|---|
| ANT-1 | 20–512 MHz 磁吸天线（粗长、馈线短） | 20–512 MHz | 接收主力：FM、VHF/UHF |
| ANT-2 | 20–512 MHz 磁吸天线（细短、馈线长） | 20–512 MHz | 馈线长，适合拉远，用作 433 MHz 闭环的 TX |
| ANT-3/4 | 2.4 GHz 板状天线 ×2 | 2.4–2.5 GHz（可能兼顾 5.8 GHz） | 2.4 GHz 闭环的首选 |
| ANT-5/6 | 宽带胶棒天线 ×2 | 以标签为准（常见 700–2700 MHz） | 512 MHz 以上扫频；若覆盖 2.4 GHz，可替代 ANT-3/4 |
| 备用 | 拉杆天线 ×2、磁吸长鞭天线 ×1 | 拉杆长度可调 | 可选 |

**FMCOMMS3 的接口**（板子顶边的一排 SMA 座，丝印为准）：
- **TX1A**：发射通道 1，本方案唯一使用的发射口；
- **RX1A**：接收通道 1，本方案唯一使用的接收口；
- TX2A / RX2A：通道 2，**不用**；
- 侧边单独的 SMA 座：外部参考时钟输入，**不接天线**。

## 1.1 为什么不能把天线接到 RX2A（只用 RX1A）

1. **软件只打开了通道 1**：AD9361 配置为 1R1T 模式（`z20_init_param.c` 中 `one_rx_one_tx_mode_use_rx_num = 1`），RX2 通道的接收链路是关闭的。天线接在 RX2A 上，**收到的数据根本不会进入 FPGA**。
2. **FPGA 处理链只接了通道 1**：`adc_tap` 只取 `adc_data_i0/q0`（即 RX1），FFT、CFAR、显示和识别全部挂在这一路上。
3. **改成双通道代价很大**：要把 AD9361 改成 2R2T，把 `adc_tap` 改成双路，FFT/CFAR 整条链要复制一份或者改成时分复用。资源和时序都会受影响，而且已验收的结论需要全部重做。
4. **双通道也解决不了"换天线"的问题**：AD9361 的两个 RX 通道**共用同一个本振（LO）**，只能同时看同一段 ±1.92 MHz（3.84 MSPS 时）的频谱。"RX1A 接低频天线、RX2A 接高频天线，同时看 FM 和 WiFi"这种用法做不到。

**结论**：接收天线一律接 **RX1A**。需要看不同频段时，**换 RX1A 上的天线**（配置 A ↔ 配置 D），同时由软件改 LO 频率。


### 1.2 磁吸天线拆装说明（20–512 MHz 天线带磁吸底座）
- 这两根天线的结构是"**鞭状天线 + 磁吸底座 + 馈线**"：鞭状天线通过底座上的螺纹接头（照片中银色的那段，通常是 BNC/TNC 或 UHF 接头）装在底座上，馈线另一端的接头接到 FMCOMMS3 的 RX1A。
- **换宽带胶棒天线时，不要把胶棒拧到磁吸底座上**（接头一般不匹配，胶棒是 SMA 公头）。正确做法：**从 FMCOMMS3 的 RX1A 上拧下磁吸天线馈线的接头**，然后把宽带胶棒直接拧到 RX1A 上。磁吸天线整体放在一边即可，不用拆开。
- 如果磁吸天线馈线末端不是 SMA 公头，它之前就已经通过某个转接头接在 RX1A 上了，换天线时连同转接头一起拧下。

## 2. 各阶段的天线配置

### 配置 A：只接收（X0–X6 以及现在）
```
TX1A：空（不接任何东西）
RX1A：ANT-1（20–512 MHz 粗长）
```
- **用途**：FM 广播频谱和瀑布图显示（X1–X3）、CFAR 列表优化（X1）、全带宽测试（X2）、信道化与识别（X5）、实时耳机监听（X6，耳机插 LINE_OUT）、70–512 MHz 扫频（X8 前半段）。
- **摆放**：底座吸在一块金属板或铁皮柜顶上，天线竖直，离开发板和屏幕至少 20 cm，尽量靠窗；馈线不要和电源线、杜邦线缠在一起。
- **为什么 TX 要空着**：这些阶段不发射。N1 的回环已经在芯片内部验证过，不需要天线；TX 空着可以避免误发射时把信号灌进旁边的 RX。

### 配置 B：2.4 GHz 空口闭环（X7 首选）
```
TX1A：ANT-3（2.4 GHz 板状）  ←— 相距 ≥ 30 cm，摆成同一方向（都竖直）—→  RX1A：ANT-4（2.4 GHz 板状）
```
#### 配置 B-直插（用户采用，2026-11-03）

```
                 两根直接拧在板上，间距约等于两个 SMA 座的距离（约 2–3 cm），朝同一方向
```
- **30 cm 不是强制要求**，它只是为安全多留的余量。真正保证安全的是**软件对 TX 功率的限制**：
  - AD9361 在 TX 衰减为 0 dB 时输出约 +7 dBm；两根天线相距 2–3 cm 时耦合损耗约 10 dB（保守估计）；
  - 直插时把 TX 衰减下限**提高到 40 dB** → RX 端最多约 7 − 40 − 10 = **−43 dBm**，远低于 RX 损坏门限（约 +2.5 dBm），也低于 RSSI 中止门限（−30 dBm），ADC 不会饱和；
  - 即使衰减设置失误到 0 dB，RX 端约 −3 dBm，仍低于损坏门限；再加上 RSSI 超限自动中止，有两道保护。
- **要求**：两根天线折到同一方向（都竖直向上）；用手拧紧；**FMCOMMS3 四角必须用铜柱撑住**，因为两根天线的重量和拧动时的力都作用在 FMC 连接器上；不要碰到附近的金属物体。
- **对结果的影响**：两根天线靠得很近，链路接近"近场"，多径很少，SNR 高且稳定，比 30 cm 时更容易标定。报告中写成"短距离空口链路"，SNR 曲线由数字注噪控制，结论仍然有效。

- **用途**：TX 自己发送 10 类已知调制，RX 接收后做识别并统计混淆矩阵；配合 FPGA 数字注噪，扫出准确率–SNR 曲线（X7）。

### 演示与录制策略（无功分器，已确定）
用户买不到功分器，**配置 E 取消**。录制按"分段录制、后期剪辑"进行，全程只用配置 A 和配置 B：
- **第一组（配置 A）**：录制所有接收类镜头，包括 FM 频谱、识别、监听、测试源、低频扫频；
- **换一次天线**：先停止程序，确认屏幕显示 `RX STOPPED`，然后把 RX1A 换成 2.4 GHz 板状天线，TX1A 接上另一根 2.4 GHz 板状天线，相距 ≥ 30 cm；
- **第二组（配置 B）**：录制 2.4 GHz 环境（WiFi/蓝牙，TX 关闭）、空口闭环识别、注噪鲁棒性、性能面板；
- 两组之间不需要重新开机。演示程序按"组"分别运行，每段视频单独保存，用户后期剪辑拼接。

### 绝对禁止
- ❌ 用 SMA 线把 TX1A 和 RX1A 直接连起来（没有衰减器，会烧坏 RX）；
- ❌ 两根天线贴在一起闭环；
- ❌ 在 ISM 频段以外发射（只允许 433.05–434.79 MHz、2400–2483.5 MHz）。

### 换天线的步骤
1. 先停止板上的接收程序（代理会告诉你命令；或者确认屏幕已显示 `RX STOPPED`）；
2. 拧下天线时扶住 FMCOMMS3，不要让 FMC 连接器受力；
3. 新天线用手拧紧即可，不要用工具；
4. 告诉代理"已换到配置 X"，再继续。

## 3. SD 卡使用

### 3.1 SD 卡里有什么
- **第 1 分区（FAT，Windows 能看到，卷标 PYNQ）**：`BOOT.BIN`（FSBL + U-Boot + 默认位流）、`image.ub`（Linux 内核和设备树）、`boot.scr`、`boot.py`、`REVISION`。这些是启动文件，**不要改动**。
- **第 2 分区（ext4，Windows 看不到）**：Ubuntu 根文件系统，包括 `/home/xilinx/sentinel`（代理推送的代码、位流和测量结果）、已安装的软件和 SSH 公钥。
- **我们自己的位流不写进 SD 卡的启动分区**，而是由 PYNQ 在运行时从 `/home/xilinx/sentinel/overlay/` 加载。所以重启后板子会回到出厂默认状态，需要重新运行程序才会加载我们的设计，这是正常的。

### 3.2 日常使用规则（N1 阶段已经因为这个出过问题）
1. **断电前先关机**：在 SSH 或串口中执行
   ```bash
   sudo sync && sudo shutdown -h now
   ```
   等串口出现 `reboot: System halted`，或者等 10 秒，再拔 12V 电源。**不要在测试运行时按 PS_RST 或直接断电**：N1 有一轮测试的结果文件因此变成了 0 字节，还触发了一次文件系统恢复。
2. **启动拨码**保持 BOOT_CFG 两位都为 OFF（SD 卡启动）。
3. **插拔 SD 卡必须在断电状态下进行**；卡要插到底，听到"咔"一声。
4. **不要在 Windows 中格式化或修复**这张卡。Windows 提示"需要格式化"或"扫描并修复"时，一律选"取消"，因为 Windows 不认识 ext4 分区。
5. 读卡器接触不良时（N1 中出现过 No Media），换一个 USB 口或换读卡器重试，**不要反复插拔正在通电的板子**。

### 3.3 整卡备份（X0 执行一次，以后每个里程碑后再备份一次）
1. 板上执行 `sudo sync && sudo shutdown -h now`，然后断电、取卡。
2. 用读卡器接到 PC。
3. 下载 **Win32 Disk Imager**（<https://sourceforge.net/projects/win32diskimager/>）：
   - Device 选 SD 卡的盘符（例如 E:）；
   - Image File 填 `D:\backup\zss_sd_YYYYMMDD.img`，**存放位置不要选 SD 卡本身**；
   - 点 **Read**（是 Read，不是 Write），约 32 GB 需要 15–30 分钟。
4. 告诉代理镜像的路径。代理会计算 SHA256 并记录到 `docs/sd_backup.md`。
5. 可选：用 7-Zip 压缩镜像，可以小很多。

### 3.4 恢复或换卡
- **卡坏了或系统损坏**：拿一张 ≥ 32 GB 的新卡，用 **balenaEtcher** 写入 3.3 节备份的 `.img`（这样会完整恢复我们的代码、SSH 公钥等）；如果没有备份，就写入原始的 `ATK-Z20-2.7.0.img`，然后让代理重新执行 P0.8 的免密配置和 `board.ps1 push`。
- 换卡后第一次连接时，SSH 可能提示主机指纹变化，在 PC 上执行 `ssh-keygen -R 192.168.2.99` 即可。

### 3.5 启动失败时的判断
| 现象 | 可能原因 | 处理 |
|---|---|---|
| 串口无输出，ping 不通 | 卡没插好，或拨码不对 | 断电，重新插卡，检查 BOOT_CFG 两位都是 OFF |
| JTAG 读到 REBOOT_STATUS 低 16 位为 0x200A | FSBL 找不到启动镜像（卡接触不良，或启动分区损坏） | 重新插卡；仍失败就用备份镜像重写一张卡 |
| 串口显示 ext4 恢复信息后能正常启动 | 上次非正常断电 | 能启动就继续用，以后注意先关机再断电 |
| 启动到登录提示但 ping 不通 | 网线或网卡 IP 设置问题 | 网线插 GE_PS 口；PC 的有线网卡设为 192.168.2.x |
