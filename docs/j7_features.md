# 上位机功能集成与验证说明

## 运行入口与固定基线

从 Git 仓库根目录执行：

```powershell
.venv/Scripts/python.exe tools/host/product.py --connect 192.168.2.99
```

这是源码入口；旧 SentinelHost.exe 不包含本次修改。窗口默认不自动开始射频场景。
开发板软件采用独立候选 `release/j7_final`，未覆盖既有正式版本。
位流仍为 `board/overlay/sentinel_v2_100m`，处理时钟 100 MHz、日常采样率 3.84 MSPS。
位流、接收库、模型、LCD 和孪生渲染核心、第三方源码均未改动。

## 卡片与数据来源

| 卡片 | 功能与验证边界 |
|---|---|
| F0 | AD9361 内部 RX PN9 校验。显示四路 PN 错误/失步状态位。硬件没有逐位错误计数器；按时间计算的名义样本数不得解释为硬件比较计数。 |
| F1 | 当前 RX1A 输入的实时频谱与瀑布。 |
| F2 | 三音与逐位黄金比对合并启动。实测频点误差 0 bin、8192 字不一致 0，运行帧率约 40–41 fps，达到 25 fps。 |
| F4 | Welch 平均开关及本轮起伏对比。 |
| F5 | CA/GO/SO 与有界 ALPHA 控件；门限线为本轮数据的软件黄金模型重建。 |
| F6 | 真实接收的数字注噪开关。历史噪声趋势指标未通过的结论保留。 |
| F7 | 信道化与 NCO 提取，显示当前窄带 IQ 和频谱。 |
| F10 | 同一输入下分别标注 CPU 与 PL 的耗时范围，二者范围不同，不称等价算法加速比。 |
| F8 | 当前广播选台、87.5–108 MHz 手动调谐和自动搜索。广播播放受既有质量门控保护。同步录音未通过，正式界面不显示录音按键。 |
| F11 | 当前现场 70–512 MHz 全景扫描，显示逐段结果及最强五个频点。属于有限、不连续快照。 |
| F12 | 当前电台资格检查及五票识别。必须十次中至少九次稳定识别为 FM，并满足质量门控，才能显示确定标签。当前未达到，界面只保留诊断结果。 |
| F13 | 输入为 F3 已测空口录波，开发板在本轮重新推理，明确标注本次不发射。500 条预测与原验证逐项一致，十类 83.4%、八大类 86.0%。 |
| F14 | AD9361 RX1A 当次采集、电脑解码 Wi-Fi 信标；只列出 FCS 通过的名称，支持热点名高亮。本轮主界面13信道采集和解码已通过，9条网络记录/27个有效信标；停止恢复、锁定及人工换线后按钮解锁全部通过。 |

F3 和 F9 的内部实现保留，卡片不再显示；F9 已并入 F2。
CFAR 控件只在 F5 出现；窄带 IQ/频谱只在 F7、F12 出现。
瀑布仅显示本次收到的最近 24 行，约 4 秒，从顶部更新；不复制已有行填满历史。
启动前曲线使用灰白虚线；无启动前数据时不绘制，表格显示“—”。

## 广播操作

1. S1 接线：RX1A 接先前广播清楚的 20–512 MHz 磁吸天线，磁座离板 20–30 cm；TX1A 可保留 2.4 GHz 胶棒，本轮不发射。
2. 点击 F8 启动，待质量检查通过。板载喇叭 J36 使用已经人工确认的 ROUT2 0 dB，P1 保持限制。
3. 下拉框选台即换台；也可输入 87.5–108 MHz 调谐，或点击搜索。搜索结果是通过导频质量复核的频率格点，不代表已经确认的电台名称；邻近格点可能属于同一电台。
4. 同步录音三轮均发生 ADC 溢出；本版不显示录制、停止录制、播放录音和返回实时四个按键，并阻止通过界面方法发起录音。
5. 原诊断代码和失败证据保留。历史独立工具的短录音成功，不等于本次主界面交互成功。

## Wi-Fi 操作与天线互锁

F14 先停止当前功能，确认恢复读回后才显示换天线框。将 TX1A 的 2.4 GHz 胶棒移到 RX1A，TX1A 空着，手机开启 2.4 GHz 热点；只有操作者确认后才采集。
服务临时使用 30.72 MSPS/24 MHz 采集 13 信道，结束恢复 3.84 MSPS/96.05 MHz。
电脑需要 MATLAB WLAN Toolbox；本机 MATLAB R2021b/WLAN Toolbox 3.3 的实际公共函数调用已验证；本轮完整解码退出码为0。历史退出钩子异常记录仍保留。
采集、传输、Python/MATLAB 解码预计约两分钟；超过估计时继续显示真实处理状态，不伪造完成。
名称来自通过 MAC FCS 的信标，不来自电脑 Wi-Fi 网卡。强度是有效信标头的 ADC 相对功率，受接收增益影响，不是校准 dBm。
本轮板端采集约63.34秒、电脑解码约41.69秒；包含确认、传输和界面处理的总等待更长。全部网络使用统一样式，不自动填入或突出某个热点名。
完成后仍锁定低频接收卡片；停止并由操作者确认换回 20–512 MHz 天线后解锁。

## 未达标项与原因

- F11 三次完整扫描约 33.7–34.0 秒，首段约 1 秒；15 秒总时限未达到。保留有限逐段扫描功能。
- F12 当前 95.8 MHz 电台十次中仅四次判为 FM，尽管十次质量检查通过；未达到九次要求，不显示可靠识别标签，不训练或降低门限。
- F8 单次完整启动实测 3.13 秒，超过 3 秒目标；自动搜台、换台已完成真实板测，但单次数据不能作为 P90 验收。
- 同步录音三轮失败：10 秒与两次 5 秒均出现 ADC 溢出。末轮已将质量证据的 SD 写入推迟到 DMA 关闭之后，仍在约 3.59 秒时报错；已隐藏录音入口。第二块数据读回 FIFO 状态为 4，而喇叭下溢计数仍为 0；故障属于同步 ADC 录制链路，不能据此否定已验收的广播收听。停止恢复成功，未生成可播放录音。
- F14 本轮为有限快照，不是持续抓包或即时扫描；已完成停止恢复、锁定和人工换线解锁。部分记录存在ADC削顶，强度仅作相对参考；只以FCS通过的帧确认名称。
- 板端日历时间未校准；本轮以 boot_id、run_id、主机接收时间和SHA256关联数据，不能将板端UTC当作准确墙钟。
- 测试期间发生人工断电；旧服务退出前的安全读回异常与采集证据保留，不能解释为正常结束。重新启动后已验证正常停止检查。
