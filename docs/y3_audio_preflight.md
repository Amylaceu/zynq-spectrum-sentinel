# Y3 音频前置核对（尚未实现或播放）

Y2 自动指标 FAIL 保留，耳机功能按95_final继续。配置A不变；首次输出前须确认
P1/LINE_OUT连接并提醒用户先不要戴耳机。此文只是电脑端接口核对，不是Y3验收。

## 实际工程发现

- `src/hw/sentinel_v1d/system_top.v` 没有 aud_mclk/bclk/lrc/dacdat端口。
- 当前 `axi_iic_fmc` 位于 **0x41620000**，顶层 iic_scl/sda 的实际引脚为
  **G21/G20**（`z20_system_constr.xdc`），不是音频用的A18/A19。
  因此旧40分册“axi_iic_audio=0x41620000”不能直接照搬：会与FMC IIC冲突。
  音频应新增独立IIC或由核实可用的板级总线访问，不能把FMC端口当音频端口。
- 音频计划管脚 U9/AA11/U6/AB11，IIC A18/A19来自95_final/已核对板级资料；
  真正实现时必须补顶层、约束、IIC实例和地址图审计，避免J22冲突。
- 原厂audio_codec_ctrl HDL是I2S控制参考，不含完整ES8388初始化寄存器表；
  未找到寄存器定义前不能猜写OUT1/OUT2使能值。
- 现有 `fm_receive.demodulate_chunk` 是离线诊断：要求>50ms，丢弃每块起止过渡，
  默认50us去加重。它不能直接充当95_final要求75us、连续流式48kHz音频链。
- Y2每次SCAP只有4096/480000=8.533ms，捕获之间有推理与存盘间隔。把这些
  不连续片段拼接不能冒充实时音频，更不能证明五分钟I2S下溢为零。
- 当前Slice占用98.68%，新增硬件仍须全系统时序审计，不能仅依据LUT66.86%
  断言资源充足。基线bit/HWH不覆盖，新硬件使用独立工程和产物目录。

## 实现门禁

1. 优先连续PL信道流→鉴相→75us去加重→抗混叠/10倍抽取→48kHz→I2S，
   复制左右声道；采样时钟必须与12.288MHz音频时钟的实际误差匹配，CDC/FIFO
   单独检查。不同MMCM时钟不可假定严格相干或没有长期速率漂移。
2. 若按三轮上限切换Y3-S，必须从连续原始IQ或有连续性证据的流取得数据，
   不能复用Y2的有间隔识别快照。板端实测解调速度须≥实时1.5倍。
3. I2S以32bit时隙承载24bit补码、48kHz左右声道帧，遵守LRCK变化后延迟1个
   BCLK的I2S协议；不要把“左对齐”旧文字误解成无延迟的left-justified格式。
4. ES8388只开OUT1、低音量、保持数字静音，确认后才解除静音；OUT2始终关闭。
5. 五分钟播放、FIFO下溢0、屏幕帧率和主观听音分别留JSON+SHA256。无人工听音
   反馈不得标DONE。
