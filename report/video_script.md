# 作品演示视频脚本（约 4 分钟）

> 视频可以剪辑，所以**拍摄顺序和成片顺序可以不同**：先用 S1 天线拍完所有低频内容，最后换"W"接法单独拍 Wi-Fi。成片中可以剪掉等待时间，但要加字幕说明；不能剪辑或加速结果本身。
> 数字取自 2026-11-04 真板实测；agent 完成 J-v8 彩排后，再核对一遍。

## 一、挑选原则（为什么这样选）
| 选用 | 理由 |
|---|---|
| **F1 实时频谱与瀑布** | 一切的基础，而且能和板上 LCD 同框对照，最直观 |
| **F5 CFAR 检测** | 核心检测算法；现场切换类型、拖动门限，画面有变化 |
| **F2 测试三音 + 逐位比对** | 一次证明两件事：频点误差 0、与黄金模型逐位一致 |
| **F10 FPGA 与 CPU 对比** | FPGA 赛道最有说服力的数字：约 23 倍 |
| **F8 广播收听** | 能直接听到声音，视频效果最好 |
| **F14 Wi-Fi 名称解码** | 最吸引人；用剪辑去掉 2 分钟的等待 |
| **F13 十类调制识别** | 作品题目里的"自动调制识别"，必须有 |

**不单独展示**：F0 接口自检、F4 Welch 平均、F6 数字注噪、F7 信道化、F11 全频段扫描、F12 现场电台识别。其中 F0、F4、F7 在原理部分用一句话带过；F11 时间够的话，可以作为 2 倍速片段放在结尾前。

## 二、成片分镜
| 时间 | 画面 | 旁白 |
|---|---|---|
| **0:00–0:25** | **硬件照片**，每张约 4 秒：① 整体全景（开发板 + LCD + 天线 + 笔记本）② Zynq Z20 开发板 ③ AD9361 射频子板 FMCOMMS3（特写 FMC 接口和 SMA 口）④ LCD 显示实时频谱 ⑤ 两根天线 ⑥ 笔记本上的上位机 | 我们的作品是基于 Zynq-7000 和 AD9361 的实时频谱智能监测与自动调制识别终端。硬件由正点原子 Z20 开发板、AD9361 射频子板、7 寸 LCD 和板载喇叭组成，电脑上运行我们自己开发的上位机。 |
| **0:25–1:10** | **原理框图** `report/figures/system_architecture.png`。旁白讲到哪一块，就用鼠标或动画框选哪一块 | 天线收到的信号由 AD9361 变成数字 IQ，经 LVDS 接口送进 FPGA。FPGA 在 100 MHz 下完成全部实时处理：先加窗做 2048 点 FFT 和 Welch 平均，得到频谱；再用 CFAR 自适应门限检测信号。检测到的信号由 16 通道多相信道化和 NCO 提取出来，交给 ARM 做十类调制识别。同时，FPGA 还完成 FM 解调送到喇叭，并直接驱动 LCD 显示。上位机通过网线控制开发板，并和 LCD 画面对照。我们上板前先验证了射频接口，FPGA 结果与黄金模型逐位一致。 |
| **1:10–1:35** | **F1**：上位机全屏录屏；右下角画中画是手机拍的 LCD。点 ▶ 启动，按 T 切到孪生画面，再按 T 切回 | 点击启动，FM 广播段的实时频谱和瀑布同时出现在上位机和板上 LCD。LCD 由 FPGA 直接绘制，约 40 帧每秒；上位机这个画面是 LCD 的数字孪生，信息区逐像素一致。 |
| **1:35–1:55** | **F5**：点 ▶，下拉切换 CA → GO → SO，拖动门限；画中画 LCD 同步变化 | 这是 CFAR 恒虚警检测。我切换三种类型、拖动门限，检出的目标数跟着变化，LCD 同步更新，说明参数是真正写进了 FPGA 寄存器。 |
| **1:55–2:10** | **F2**：点 ▶，三根尖峰；字幕放大"频点误差 0 bin｜8192 字 0 不一致" | 注入三根测试音，FPGA 检出的频点与理论值误差为 0；8192 个输出字与黄金模型逐位比对，没有一个不一致。 |
| **2:10–2:25** | **F10**：点 ▶；字幕放大"CPU 15.8 ms｜FPGA 0.68 ms｜约 23 倍" | 同一帧数据，CPU 处理约 15.8 毫秒，FPGA 约 0.68 毫秒，快了大约 23 倍。 |
| **2:25–2:50** | **F8**：点 ▶，等喇叭出声，保留 5–8 秒广播原声；画中画 LCD 底栏显示频率 | 接下来是广播收听。系统先检查每个电台的立体声导频质量，自动选出最好的台，FPGA 完成 FM 解调和去加重，从板载喇叭播放。播放样本在增长，下溢为 0。 |
| **2:50–3:15** | **F14**：插入 2 秒换天线特写 → 点 ▶ → 弹框点继续 → 进度条 → **剪辑**（字幕"略去约 2 分钟采集与解码"）→ 结果列表，鼠标指向自己的热点 | 然后换上 2.4 GHz 天线，扫描 13 个 Wi-Fi 信道。这些名称是 AD9361 从空中采集、再解码出的帧校验通过的信标，不是电脑网卡扫描的结果。这一条就是我手机开的热点。 |
| **3:15–3:40** | **F13**：点 ▶，混淆矩阵逐格生成；字幕"十类 83.4%｜八大类 86.0%" | 最后是调制识别。我们把之前 2.4 GHz 空口实测录下的数据送进开发板，现场推理。十类准确率 83.4%，八大类 86.0%，与当时的测试结果完全一致。 |
| **（可选）3:40–3:50** | **F11** 全频段扫描，2 倍速，字幕"2 倍速" | 系统还能对 70 到 512 MHz 逐段扫描，得到整个频段的全景。 |
| **3:40–3:55** | 回到整体全景照片或实拍画面，字幕显示作品名 | 以上就是我们的作品：FPGA 实时处理并直接驱动屏幕，ARM 完成智能识别，上位机实现可视化控制和对比。谢谢观看。 |

总时长约 3 分 55 秒；加上 F11 约 4 分 05 秒。需要压到 3 分钟时，按顺序删掉：F11 → F10 的画面（数字放进 F2 的字幕）→ 原理段缩到 30 秒。

## 三、拍摄顺序（按天线接法分两段拍）
1. **S1 接法**（磁吸天线在 RX1A，胶棒在 TX1A）：拍 F1、F5、F2、F10、F8、F13（以及 F11）。每段点 ▶ 前先停 2 秒，方便剪辑。
2. **换成"W"接法**（胶棒拧到 RX1A，TX1A 空着），打开手机 2.4 GHz 热点：拍 F14，从点 ▶ 一直录到结果出来，不要中途停止录屏。换天线的过程单独拍 3–5 秒特写。
3. 拍完后，按 F14 弹框换回 S1，正常关机：`sudo sync && sudo shutdown -h now`。
4. 硬件照片可以在任何时候拍，背景尽量干净，LCD 上要有实时频谱画面。

## 四、录制建议
| 项目 | 建议 |
|---|---|
| 录屏 | 用 OBS 录 1920×1080、30 fps；上位机按 F11 全屏 |
| LCD | 手机上三脚架正对 LCD，关闭自动曝光（LCD 容易过曝），锁定对焦；剪辑时作为右下角画中画，约占画面 1/4 |
| 声音 | 旁白后期单独录，更清晰；广播原声用手机贴近板载喇叭录，F8 段保留 5–8 秒原声，旁白在原声前后说 |
| 字幕 | 关键数字用大号字幕：40 fps、0 bin、8192 字 0 不一致、23 倍、83.4% / 86.0% |
| 剪辑说明 | 剪掉的等待必须加字幕（如"略去约 2 分钟采集与解码"）；2 倍速片段要标注"2 倍速"；结果画面不加速、不修改 |
| 安全 | 全程不发射；不要直接拔电，不要按复位 |
