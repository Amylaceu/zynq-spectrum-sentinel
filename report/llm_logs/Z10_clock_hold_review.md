# Z10：时钟、复位与保持时间审查

## 用户目标

用户要求减少后续功能开发中的整机重建时间，按 Z10 完成 100 MHz
处理时钟、流水和复位修改，并询问 WHS 正裕量较小时的处理方式。
验收仍为整机 WNS ≥ +1 ns、WHS ≥ 0；不放宽门槛，不修改第三方源码。

## 修改与纠正

- 独立候选为 `sentinel_v2_100m`。保留既有 v1b/v1d 产物和原始失败结论；
  软件按镜像区分 150/100 MHz，旧测量不重新换算。
- CFAR 搜索与比较分拍，18 组黄金对照通过；源节拍 16384 字精确一致。
- 第一轮布线暴露 DSP 复位进入 ADC FIFO 复位 D 脚。改为域内同步复位后，
  8192 字、单侧复位和背压回归通过。曾有带 XPM 断言的旧仿真打印 PASS，
  已判无效并保存历史日志；不据旧 PASS 宣称通过。
- 第二轮 WNS +0.012 ns、WHS +0.028 ns：基本时序通过，Z10 的 +1 ns
  目标未通过。最差保持路径来自 AD9361 时钟监测计数器，不能用降低
  DSP 时钟或任意组合延迟链代替针对短路径、时钟偏斜的检查。
- 发现 DSP/audio MMCM 对同一 50 MHz 输入重复创建主时钟。独立小工程
  验证 `PRIM_SOURCE=No_buffer` 后用于第三轮，仅改变时钟输入配置，
  不添加 false_path/multicycle。运行中冻结硬件输入并验证哈希。
- 第三轮中途的 setup/hold 报告仅为过程诊断；最终实现及独立审计完成前，
  不签发 acceptance，不部署候选。当前阶段至多三次完整实现。

## 软件交接与验证

- 数字单音、三音及 8192 字回放入口支持显式选择 v2；尚未上板运行。
- `board/measurements/z10_runtime_full_r1.json` 保存修改前 254 项 PC 回归。
- 检查发现 FM 与测试音的停止顺序不一致。新增共享
  `shutdown_audio_outputs`，统一先静音/关闭 DAC，再释放 I2S 引脚；
  编解码器失败仍尝试引脚清理，错误保留到运行收据。
- 新增 7 个顺序、异常和部分初始化用例；修改后 261 项回归通过，
  `board/measurements/z10_runtime_full_r2.json` 和 SHA256 保留源码与日志哈希。
  板端入口通过 Python 3.8 AST 检查。以上均不代表喇叭已经出声。

## 后续验收边界

读取最终布线报告，再独立审计时钟、CDC、DRC、引脚、未约束路径和例外。
达到实现门槛后，才可在确认配置 A 后做数字/RF 板测；板载喇叭先进行
1 kHz/3 秒人工听音，再进行 FM 连续监听。后续演示、告警、Web 等功能
优先用 PS 和现有接口实现，降低再次修改 PL 的频率。

- 第三轮最终WNS+0.026/WHS+0.042ns，+1ns目标FAIL；独立审计完成，
  重复主时钟问题消除，仍有CDC与板外I/O假设待复核。没有开第四次实现或部署。
- 用户问100MHz是否要求修改先前已验证功能：旧v1b/v1d位流和产物保持不变，
  软件按镜像选择时钟参数；v2含时钟/CFAR/复位修改，须另做板端回归，不能复用旧验收。

  拥塞报告无5级以上窗口，纠正“100MHz失败必然是全局拥塞”的笼统推断。
- 审计工具补充DRC错误/缺失和路由错误/缺失检查，新增4项测试，
  最新完整回归265项通过，独立证据z10_runtime_full_r3.json及SHA256。
