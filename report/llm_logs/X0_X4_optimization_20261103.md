# X0–X4 离线优化协作记录

## 用户目标

用户说明“我要离开，我会保持板子上电，你继续优化X0-X4的部分内容”。本轮不需要用户现场操作，保留所有既有正式验收结果和 X5 在途工作。

## 执行与修正

1. 核对实际仓库和正式状态：X0 DONE，X1–X4 FAIL；原六份关键验收/完整性 JSON 与 SHA256 一致。未把归档完整性 PASS 当成功能 PASS。
2. X2 准备隔离计数器/CFAR 候选，完成边界和逐周期仿真。OOC 第1次缺参数、第2次 Tcl API 不兼容，均保留失败日志；第3次使用端口过滤完成四模块比较。它们不是第三轮整机实现。
3. X4 缓存推理保持模型、前处理和细分不变。PC 2000 段 logits 等价，板端 50 段×3次×3后端完整输出一致。板端初次布局假定错误、二次 ARM32 bincount 类型不兼容，在进入计时前修正；第3次保留全部450条耗时。
4. 发现缓存中位加速只有约0.1%–1.4%，单次时延仍超100ms，因此保留部署默认 Predictor。没有追加训练、降低识别阈值或以局部实验替换原 FAIL。
5. X2 分段计数器建立时间改善，但保持时间仍失败；CFAR候选WNS由+0.074退化为−0.174ns，决定不采用。OOC虚拟输入输出不能代表整机时序，不下载候选位流。
6. 完成 PS 测试172项；新增汇总工具独立重算统计、核对源码/模型/包哈希并生成 ZIP manifest，方便异机交接。

## 结果与限制

详细结果见 `docs/x0_x4_optimization.md` 和 `board/measurements/x0_x4_optimization_r1.json`。本轮不启动射频、不加载位流、不更改硬件连接，不要求目视或听音。开发板保持上电。原 X1–X4 未达标项继续保留；没有宣称全带宽、整机时序或十类识别验收通过。
