# I1 常驻接收服务协作记录

## 需求与约束

用户要求按 I 阶段方案推进，保持 S1 接线，优先可用功能。仅接收授权已明确；不重新构建位流、不训练模型、不调整 CFAR，不覆盖原有发布。固定展示方案中空口需明确回放，不能把控制入口当作实时发射已完成。

## 主要实现

新增 ReceiveBackend/ResidentController 和根用户本地控制 socket，复用单个 Session、模型与 codec。check/fm/listen/perf/idle 切换时先静音、读回保护状态，再检查实际就绪；超时返回静音待机，异常和最终 stop 统一释放。进入 listen 暂停源以避开音频 FIFO 复位忙窗口，不复位射频芯片。网络接口只接受预设场景 ID，不开放发射参数。pano/wifi 与回放未接入时明确拒绝。

## 出错与纠正

第一轮在启动前因 PYNQ 已加载位流路径与候选路径不一致而拒绝 MMIO。改为查询实际加载路径、核对其为冻结镜像，再用只读停止检查确认状态。第二轮错误地指向未部署候选，服务未启动；增加部署结果 JSON 与 SHA256 的前置核对，先部署第三轮候选再测试。两次失败结果保留，没有覆盖或将其记为成功。

第三轮候选 130 个文件摘要核对成功。50 次随机切换中五个场景各 10 次，全部数字就绪。板内 listen P90 2.200 秒，SSH 往返 P90 4.875 秒，因此不声称上位机点击时间通过。位流、射频、模型、codec 各初始化一次，结束后 GPIO/SRC/audio 为 0，174 个带摘要文件取回核验一致。

## 人工反馈与边界

用户反馈随机切换时隔一段时间听到一句广播，要求加大音量。说明测试只有 listen 场景放音，安排独立连续试听而非扩大数字就绪的听音结论。−9 dB 连续试听自动指标通过，用户确认广播连续但音量小，要求最高音量；追加保护上限 −6 dB 的独立试听，最终结论另存听音证据。独立旧音频入口的结果不冒充常驻监听长测。

原回归 137 passed、1 skipped；增补 −9 dB 寄存器读回及用户要求的源码默认音量更新后，针对性回归 48 passed、1 skipped。Windows 跳过 Unix socket 测试；真实 Linux 板上本轮控制 socket 已用于 50 次切换。

## 尚未完成

I1 尚缺全景、WiFi、明确回放接入、完整性能汇总、网络 RTT 和上位机端到端测量；持续听音、长时间服务与全部讲解流程不以五场景短测替代。历史失败保留。正式 v2 发布可回退，当前第三轮候选不覆盖；源码音量更新留待下次打包部署。

证据：`board/measurements/i1_acceptance_summary.json`、`i1_board_r1/r2/r3/`、`i1_volume_m9_r1/`、`i1_volume_m6_r1/` 及各 SHA256。使用说明为 `docs/i1_resident_service.md`。

后续用户确认 −6 dB 广播连续但依然偏小。查阅 ES8388 Rev5 第28页后新增 ROUT2-only、最高 0 dB 的显式通路，保留 OUT1 −6 dB 上限，拒绝正增益并验证无效值在写寄存器前被拒绝。0 dB 独立60秒测试全部自动通过，用户确认音量合适；源码配置及常驻、listen、A组转发已更新但尚未重部署。最终回归146 passed、1 skipped，先前两个沿用−12 dB期望的测试失败被如实保留并更新为用户的新要求。
