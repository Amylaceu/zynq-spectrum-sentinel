# 现场讲解稿 v4（约 4 分钟，配合 J-v8 上位机，含 LCD 对照）

> 方括号【】里是操作，不念。数字取自 2026-11-04 真板实测，彩排后由 agent 按实测值核对。
> **对照原则**：每启动一张卡片，先指上位机、再指板上 LCD，说一句"两边是同一组数据"。LCD 是 FPGA 直接驱动的，上位机是它的数字孪生。需要逐像素对照时，按 **T** 切到孪生画面，再按 **T** 切回。
> 开场前接法"W"：2.4 GHz 胶棒拧在 **RX1A**，TX1A 空着，磁吸天线放在板旁；手机已开 2.4 GHz 热点。
> 建议摆位：LCD 立在笔记本旁边、面向评委，摄像头或评委能同时看到投影和 LCD。

---

## 0. 开场，同时启动 Wi-Fi 采集（0:00–0:20）
【点 F14 ▶ 启动 → 弹框点"继续"】

各位评委好，我们的作品是基于 Zynq-7000 和 AD9361 的实时频谱智能监测与自动调制识别终端。
我先让它在后台做一件比较费时的事：扫描 2.4 GHz 的 13 个 Wi-Fi 信道，从空中抓取 Wi-Fi 信标。
【指 LCD】板上屏幕也显示了当前任务和采集进度，和上位机的进度条同步。

## 1. 系统架构（0:20–1:05，正好覆盖采集时间）
【不操作，依次指 AD9361 子板、Zynq 板、LCD、笔记本】

整个系统分三层。
- **射频层**：AD9361 负责接收，通过 LVDS 接口把 IQ 数据送进 FPGA。
- **FPGA 层**：在 100 MHz 时钟下做全部实时处理，包括信号源选择、加窗 FFT、Welch 平均、CFAR 恒虚警检测、16 通道多相信道化加 NCO、FM 解调和去加重，最后**直接驱动这块 LCD**，并把音频送到喇叭。
- **ARM 层**：负责调制识别、参数控制，以及把 LCD 画面和结果同步给上位机。

FPGA 资源用了约 71% 的 LUT，时序余量 +0.21 ns。
上位机左边每一张卡片是一个功能：点"启动"，板子现场执行，LCD 和上位机同时变化；右边显示启动前后的对比。

## 2. 换天线（1:05–1:20）
【弹框"采集完成"出现 → 磁吸天线拧回 RX1A、胶棒拧回 TX1A → 点确认】

Wi-Fi 数据已经采完，电脑在后台解码。我把天线换成 20–512 MHz 的天线，接着看低频段。

## 3. 实时频谱，与 LCD 对照（1:20–1:45）
【点 F1 ▶ 启动 → 指 LCD → 按 T 切到孪生 → 再按 T 切回】

这是 FM 广播段的实时频谱和瀑布图。大家对照看板上的 LCD：同一组频谱、同一个瀑布，LCD 由 FPGA 直接绘制，帧率约 40 帧每秒，不经过 CPU。
上位机的这个画面是 LCD 的数字孪生，右侧和底部的信息区与 LCD 逐像素一致。

## 4. CFAR 检测（1:45–2:05）
【点 F5 ▶ 启动 → 下拉切换 CA / GO / SO → 拖动门限滑块 → 指 LCD】

这是 CFAR 恒虚警检测，红线是自适应门限。我现场切换三种 CFAR 类型，再拖动门限，检出的目标数随之变化。
LCD 上的目标列表和右下角的类型、目标数同步更新，说明参数是真正写进 FPGA 寄存器的，不是只改了上位机的显示。

## 5. 数字注噪（2:05–2:15，时间紧可跳过）
【点 F6 ▶ 启动 → 指 LCD】

在 FPGA 内部给真实接收信号叠加数字噪声，上位机和 LCD 上的底噪同时抬高，弱信号被淹没。这用来测试鲁棒性，全程不发射。

## 6. 广播收听（2:15–2:40）
【点 F8 ▶ 启动，等喇叭出声 → 指 LCD 底栏】

现在自动选台。系统先检查每个候选台的立体声导频质量，选出最好的台，FPGA 完成 FM 解调和去加重，从板载喇叭播放。
LCD 底栏显示正在收听的频率，和上位机一致；右边的播放样本数在增长，下溢为 0。信号变差时，质量门控会自动静音。

## 7. Wi-Fi 结果（2:40–3:00）
【F14 卡片变绿"结果就绪"后点它 → 指 LCD】

后台解码已经完成。这些 Wi-Fi 名称都是 AD9361 从空中采集、再解码出来的、帧校验通过的信标，不是电脑网卡扫描的结果。这一条就是我手机开的热点。LCD 上也显示了解出的网络数量。

## 8. 接口、精度与性能（3:00–3:35）
【点 F0 ▶ 启动 → 指 LCD】
首先是接口自检：AD9361 内部 PN9 回环，4 路数据 0 错误，LCD 上同样显示"PN 0 ERR"。这证明 FPGA 和射频芯片之间的高速接口完全正确。

【点 F2 ▶ 启动 → 指 LCD】
接着是精度：注入三根测试音，上位机和 LCD 上同时出现三根尖峰。检出频点和理论值误差为 0；8192 个输出字与黄金模型逐位比对，0 个不一致。

【点 F10 ▶ 启动】
最后是性能：同一帧数据，CPU 处理约 15.8 毫秒，FPGA 约 0.68 毫秒，大约快 23 倍。

## 9. 十类调制识别（3:35–3:55）
【点 F13 ▶ 启动 → 指 LCD】

最后是调制识别。现场不能发射，所以我们把之前 2.4 GHz 空口实测录下的数据送进开发板，现场推理，混淆矩阵一格一格生成，LCD 上同步显示当前类别和准确率。十类准确率 83.4%，八大类 86.0%，和当时的测试结果完全一致。

## 10. 结束（3:55–4:05）
【点顶栏"■ 全部停止"，LCD 回到待机】

以上就是我们的作品：FPGA 完成实时频谱处理并直接驱动屏幕，ARM 完成智能识别，上位机实现可视化控制和对比。谢谢各位评委。

## 出问题时怎么说
| 情况 | 操作和说法 |
|---|---|
| 某张卡变红 | 再点一次启动；仍失败就说"这一项我们跳过，后面答辩可以再演示"，然后点下一张卡 |
| LCD 和上位机画面不同步 | 看顶栏连接灯；绿灯就再点一次该卡；红灯就说"上位机在重连，大家先看板上 LCD"，指着 LCD 继续讲 |
| 讲到第 7 段时 Wi-Fi 还没解完 | 先讲第 8 段，讲完再点 F14 |
| Wi-Fi 解码失败或没有出现自己的热点 | "这一轮采集是有限快照，信标没有被抓到"，直接进入第 8 段 |
| 广播没声音 | 在 F8 下拉框换台；还不行就说"现场信号较弱"，点下一张卡 |
| 上位机断线 | LCD 照常工作，指着 LCD 继续讲；连接灯自动变绿后再操作 |

## 答辩追问可以点开的卡片
| 评委可能问 | 点什么 |
|---|---|
| LCD 和上位机是什么关系？ | 按 T 切到数字孪生："LCD 由 FPGA 直接驱动；ARM 把同一帧画面和结果通过网络同步给上位机，右侧和底部信息区逐像素一致" |
| 加窗、平均有什么作用？ | F4 Welch 平均：上位机和 LCD 上底噪同时变平滑，起伏从约 7.1 dB 降到约 5.4 dB |
| 信道化怎么做的？ | F7 信道化 + NCO：16 通道里提出一路，480 kSPS 窄带 IQ 和星座图 |
| 能扫多宽的频段？ | F11 全频段扫描：70–512 MHz 现场逐段扫描，约 30 多秒 |
| 现场电台能识别吗？ | F12（如果在左栏）；不在左栏就说"现场 FM 电台的识别稳定性还没有达到我们 9/10 的门槛，所以只展示实测录波的十类识别" |
| 23 倍是怎么算的？ | 点 F10 卡片的 ⓘ：CPU 和 FPGA 两边的计时口径不同，这是同一输入下的实测比值 |
| 为什么要换天线？ | 2.4 GHz 和广播频段差得远，一根天线兼顾不了；系统会锁住接收功能，必须确认换好天线才能继续 |
| 有没有发射？ | 全程不发射，TX 衰减固定 89.75 dB |
