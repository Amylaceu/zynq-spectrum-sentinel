**演示层面的问题**（本阶段要解决的）：
1. **D1 演示太慢**：`demo.py` 每段都以子进程方式重新加载位流、初始化 AD9361 和模型，段间切换要 15–20 s，视频节奏拖沓。
2. **D2 界面信息密度低、层级不清**：PS 区域只能用 12 px 单一字号的文字；TX 状态只靠颜色，而冻结的 PL 只支持黑、白、黄、青四色，看不出红/绿；没有大字号的当前识别结果和统计面板。
3. **D3 只有一块 7 寸屏**：评委和视频只能看小屏；不能远程查看，没有数据记录、回放和导出，体现不出"终端 + 上位机"的系统完整度。
4. **D4 现场演示没有兜底**：答辩现场射频环境未知（FM 弱、WiFi 很多），一旦接收不好，演示就会失败。

**结论：用户提出的两项扩展都合适**，而且投入产出比高：
- **LCD 界面优化**：在四色和现有 PS 区域（右侧 240×400、底部 800×80）的约束下，靠**排版、字号层级、反色块、闪烁和图形**来提升效果，**不需要改位流**。PL 绘制的频谱和瀑布图保持不变。
- **上位机**：板端增加一个只读的数据服务，PC 上运行 Python 上位机（大屏频谱、瀑布、目标表、星座图、统计、录制回放）。这正好补上 95_final Z4 中"远程监看"的应用点，**不占用 FPGA 资源**；**录制回放**模式同时解决现场兜底（D4）和评委复现的问题。
- **不建议**：上位机控制发射、触摸屏、第二块屏、HDMI 输出、重新训练。

## G1 演示运行时常驻化与连续录音（必需，解决 D1）

**原因**：现在 `src/ps/sentinel/app/demo.py` 每段都启动子进程并带 `--load`，因此每段都要重新加载位流、初始化 AD9361、加载模型和预热。
**操作**：
1. 新建 `src/ps/sentinel/app/runtime_v2.py`：`SentinelRuntime` 上下文管理器在**整组开始时**加载一次 overlay，初始化一次 AD9361 和 ES8388，预热一次模型；之后各段只调用 `runtime.set_mode(...)`、`set_lo()`、`set_source()`，复用同一个进程。
2. 段切换流程固定为：静音 → 停止当前数据流 → 改配置 → 等 PL 帧号增长 ≥ 2 → 开始。每段结束都**读回** GPIO/SRC/audio 和 TX 衰减（保留现有的安全检查，不能因为常驻而省掉）。
3. 异常处理：任何一段失败，都先走一遍完整的 `stop` 清理（与 `sentinel.sh stop` 等价），再决定跳过该段（屏幕显示 SKIPPED）还是退出。B 组的发射段在异常时**必须先把 TX 衰减恢复到 89.75 dB**。
4. 旧的子进程方式保留为 `--isolated`（回退用），默认改为常驻方式。
5. 连续 WAV：`--record-audio <path>`，FM 段实际放音的 PCM 写入 48 kHz 16 bit 单声道 WAV（补上 F2 缺的项）。
6. 同时修复 F2/F3 记录的问题：段标题和倒计时以实际墙钟为准。

**指标**：

| 指标 | 目标 |
|---|---|
| A 组每遍墙钟时长（内容 95 s） | **≤ 110 s**（原 173.8 s） |
| B 组每遍墙钟时长（内容 125 s） | **≤ 145 s**（原约 157 s） |
| 段间切换时间 | 中位数 ≤ 3 s，最大 ≤ 6 s |
| 连续 3 遍 | 无崩溃；每段结束 GPIO/SRC/audio = 0 的检查全部通过；发射段 TX 最小衰减 ≥ 40 dB |
| WAV | 时长与实际放音时间误差 ≤ 0.1 s，零下溢 |

先只跑 A 组 3 遍（配置 A）。B 组的常驻化先做离线测试，等 G5 换到配置 B 时再上板。

## G2 LCD 界面 v3（必需，纯 PS，解决 D2）

**约束（不可突破）**：PL 绘制左侧频谱和瀑布区，不改。PS 只能写**右侧 240×400** 和**底部 800×80** 两块 UI 区，调色板固定为 0 黑、1 白、2 黄、3 青（`lcd_x5.py` 的 `pack_ui`）。
**设计原则**：用**字号层级、反色块（底色块 + 黑字）、图形和闪烁**表达状态，不依赖红/绿；同一类信息始终在同一个位置；录像时离屏 40 cm 要能看清。

### 2.1 布局
```
┌──────────────────────── PL：频谱 + 瀑布（不变） ─────────────────────┬── 右栏 240×400（PS）──┐
│                                                                      │ [页签] SIG │ TGT │ STAT│
│                                                                      │ ─────────────────────│
│                                                                      │ 页 SIG：信号卡片 ×4   │
│                                                                      │  95.800M  FM  ███▌ 92%│
│                                                                      │  200k  −41dBFS  ●NEW  │
│                                                                      │ 页 TGT：当前目标      │
│                                                                      │  大字号调制名 24px    │
│                                                                      │  置信度条 + 5 票历史  │
│                                                                      │  星座图 200×200       │
│                                                                      │ 页 STAT：类别直方图   │
│                                                                      │  （B 组：实时准确率） │
├────────────────────────────── 底部状态栏 800×80（PS） ───────────────┴──────────────────────┤
│ [■MONITOR]  LO 96.050M  3.84MSPS  29.0fps  58.3°C  [TX OFF]  PC●  up 00:12:34             │
│ 事件： 12:03:41 NEW 95.80M FM │ 12:03:44 LOCK 95.80M │ 12:03:50 MOD CHG 433.92M OOK→?   │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 具体规则
- **模式徽章**：反色块（MONITOR/LISTEN = 青底黑字；OTA TX = 黄底黑字）。
- **TX 状态**（代替红/绿）：`TX OFF` 是白色细边框、白字；`TX ON 52dB` 是**黄色实心块 + 黑字，以 1 Hz 闪烁**。闪烁只改 UI bank，不影响 PL。
- **字号**：三档，标题 20 px、正文 14 px、辅助 12 px。字体沿用 DejaVuSansMono-Bold，关闭抗锯齿（`fontmode='1'`）。中文只用于少数固定标签：先检查板上有没有 CJK 字体；没有的话，在 PC 端把需要的几个字预先渲染成 1 bit 位图放进 `src/ps/sentinel/ui_assets/`，**不在板上安装字体包**。
- **信号卡片**：两行（频率/调制/置信度条；带宽/功率/NEW 标记）；调制大类用颜色区分（模拟 = 白，AM/OOK = 黄，数字 = 青），同时加图标字母，例如 `A`/`D`，不能只靠颜色。新出现的目标显示 `●NEW` 3 s。置信度 < 0.5 时显示 `?`（保持现有规则）。
- **页签自动轮换**：monitor 模式每 6 s 换一页；demo 模式由段脚本指定页面（例如段 2 显示 TGT 页，B 组段 5 显示 STAT 页的实时准确率和发送 vs 识别）。
- **事件区**：底部第二行显示最近 3 条，`ui_events.py` 已有基础，统一格式为"时间 类型 频率 内容"。
- **开机画面**：段 1 自检时右栏逐项显示 `[OK] AD9361 ID`、`[OK] BITSTREAM`、`[OK] TX 89.75dB`、`[OK] TEMP`，每项间隔 0.5 s，有"仪式感"。
- **刷新策略**：UI 内容没有变化时不提交新 bank；列表 5 Hz、状态栏 2 Hz、闪烁 1 Hz，合并成一次提交。
- 新代码放在 `src/ps/sentinel/ui_v3/`（`layout.py`、`widgets.py`、`theme.py`），`lcd_x5.py` 的 `pack_ui`/`X5LCD` 只复用不修改；旧的 `draw_ui` 保留，用 `--ui v2` 回退。
- **为上位机孪生预留（G4 依赖）**：
  - **UI 状态机**：`ui_v3/state.py` 保存当前页签、选中目标、监听状态、录音状态、提示信息，**是 LCD 和上位机的唯一状态源**。
  - **可点击控件表（hit map）**：`layout.py` 中每个控件都登记一个矩形（LCD 物理坐标 800×480）和一个动作名，例如页签 `tab:SIG`、信号卡片 `card:<key>`、频谱区 `spectrum:<x>`。
  - **软按键**：底部状态栏右侧增加 4 个软按键：`[LISTEN]`、`[SNAP]`、`[REC]`、`[NEXT]`。LCD 本身没有触摸，按键由上位机点击触发，但按下后 LCD 上同样显示按下和激活状态（反色 0.3 s），**现场观众看大屏和小屏是同步的**。
  - **点击提示**：被点中的控件在 LCD 上出现 1 px 闪框 0.5 s，让人看出"是上位机在操作终端"。

## G3 板端数据服务 hostlink（必需；含孪生画面、点击、音频流）

**位置**：`src/ps/sentinel/app/hostlink.py`，作为常驻运行时（G1）中的一个**后台线程**，通过 `--hostlink` 开启（`monitor`、`listen`、`demo`、`show` 都支持）。只用 Python 3.8 **标准库**（`socket`、`selectors`、`threading`、`json`、`http.server`），**板上不安装新包**。

### 3.1 协议（写入 `docs/hostlink_protocol.md`，版本号 `hostlink/1`）
- TCP 端口 **9000**：每条消息 = 一行 JSON 头（`type`、`seq`、`t_mono`、`len`），后面跟 `len` 字节的二进制负载（小端）。
- 板 → PC 消息：

| type | 频率 | 内容 |
|---|---|---|
| `hello` | 连接时 | 协议版本、位流 SHA256、采样率、LO、FFT 点数、发布版本号 |
| `spectrum` | 10 Hz | 1024 点 int16 功率（0.01 dB 单位，由 2048 点做最大值抽取），以及帧号 |
| `detections` | 5 Hz | CFAR 目标列表：频率、带宽、功率、首次出现时间 |
| `amc` | 每次识别 | 目标 key、调制类别、置信度、5 票结果 |
| `iq` | 2 Hz | 当前选中目标的 512 点 complex64（星座图用） |
| `telemetry` | 1 Hz | 帧率、温度、RSSI、采样溢出计数、CPU、内存、TX 状态和衰减、音频状态 |
| `event` | 发生时 | 与 LCD 事件区相同 |
| `demo` | 段切换时 | 组、段号、标题、剩余时间；B 组另有"发送类别 / 识别类别" |
| `ui_frame` | **UI 每次提交时** | 与 LCD 完全相同的 PS UI 数据：`pack_ui` 输出的 10 000 个 32 bit 字（2 bit/像素，40 KB，zlib 压缩后通常 < 5 KB），以及 UI epoch 号。上位机解包后**逐像素等于 LCD 的 PS 区** |
| `pl_frame` | 10 Hz | 重建 PL 区所需的数据：显示用的频谱、峰值、门限（Q8.8，与 `sim/golden/render.py` 的输入格式一致）、CFAR 目标和瀑布新行；上位机用同一份黄金渲染模型画出 PL 区 |
| `ui_state` | 状态变化时 | `ui_v3/state.py` 的状态（页签、选中目标、监听、录音、软按键状态），供上位机高亮控件和弹出提示 |
| `audio` | 监听时连续 | FM 解调后**实际送往喇叭的同一份 PCM**：48 kHz、16 bit、单声道，每包 20 ms（1920 字节），带样本序号和质量门控状态（静音段也发送，标记 muted） |
| `file` | 按请求 | 板端生成的文件（IQ 录制、WAV、快照）分块下载，附 SHA256 |

- PC → 板命令（**白名单**，其余一律拒绝并记录）：
  - 基本：`ping`、`get_status`、`stop`；
  - 界面：`click <x> <y>`（LCD 物理坐标；板端按 hit map 解析成动作，效果与本地操作相同）、`select_target <key>`、`set_page SIG|TGT|STAT`；
  - 接收：`set_lo <Hz>`（**仅 monitor 模式，并限制在 70 MHz–2.7 GHz 的接收范围内**）、`listen <MHz>`（**仅 87.5–108 MHz**）、`listen_target <key>`（目标必须在 FM 频段并已识别为 FM）、`mute`/`unmute`、`set_volume <dB>`（**夹紧在 −30 到 −6 dB**，与音频保护范围一致）；
  - 数据：`audio_stream on|off`、`snapshot`（保存当前 IQ 和功率帧到 `measurements/host_snapshots/`）、`iq_record <key> <秒>`（选中目标的信道化 IQ，**≤ 10 s**，写到板端后用 `file` 下载）、`get_file <名称>`（仅允许 `measurements/host_*` 目录下的文件）。
- **安全**：hostlink **不提供任何发射命令**，也不能修改 TX 衰减或 TxGuard；B 组发射只能在板端 SSH 终端输入 `yes` 后启动。只监听局域网地址；可以选配一个共享 token（放在板端 `config.yaml`，**不写进仓库文档**）。
- **背压**：每个客户端一个有界队列（≤ 2 MB），满了就丢掉旧的 `spectrum`/`iq` 帧（计数），**绝不阻塞采集或 LCD 线程**。最多 3 个客户端。
- **数据来源**：优先读 PL 已有的功率帧快照（参考 `monitor_x1.py` 的 `read_capture` 路径）、CFAR 列表和识别结果；如果无法在不影响 LCD 的前提下拿到功率帧，就对现有 RX IQ 快照做 PS FFT（`lcd_spectrum.spectrum`），并在 `hello` 中标注 `spectrum_source=ps_fft`。**不改位流**。

### 3.2 轻量网页（手机看）
- HTTP 端口 **8080**：`/` 返回一个单文件静态页（Canvas 画频谱 + 目标表），`/events` 用 SSE 推送，频率 5 Hz。
- 手机或另一台电脑打开 `http://192.168.2.99:8080` 就能看到画面（地址以 `docs/board_info.md` 为准）。

### 3.3 指标

| 指标 | 目标 |
|---|---|
| hostlink 开启时 LCD 帧率下降 | ≤ 1 fps |
| hostlink 线程 CPU | ≤ 15%（单核） |
| 采样溢出 | 0 |

## G4 PC 上位机 SentinelHost：可点击的 LCD 孪生 + 功能工作台（必需，2026-11-04 按用户要求修订）

**设计思路**：上位机主画面**和 LCD 完全一致**（"数字孪生"），但可以用鼠标点击操作；周围加一圈 LCD 上没有空间放的功能（音频保存、IQ 录制、统计、回放、导出）。评委看到的是"同一个终端，两种呈现：板上小屏 + PC 大屏可交互"。

**位置**：`tools/host/sentinel_host/`（Python 3.12，Windows）。依赖：`PySide6`、`pyqtgraph`、`numpy`、`sounddevice`（PC 扬声器实时播放），写入 `tools/host/requirements.txt`，装进仓库 `.venv`。

### 4.1 主界面布局（1920×1080）
```

├──────────────── LCD 孪生画布 800×480，整数倍放大 ×2 = 1600×960 ────────────────┬── 功能侧栏（320 px，可折叠）─┤
```

- **一致性的实现方式（关键）**：
  - **PS 区**：直接显示板端发来的 `ui_frame`（与写进 LCD BRAM 的是同一份字），按同一四色调色板映射成 RGB，**逐像素一致**，不在 PC 上重新排版；
  - **PL 区**：用仓库已有的 `sim/golden/render.py` 黄金渲染模型（PL LCD 的像素级参考），输入板端发来的 `pl_frame`，画出与 LCD 相同的频谱、门限和瀑布。由于数据经过抽样传输，PL 区为**视觉一致**（同一调色板和坐标映射），不要求逐帧逐像素一致；
  - 画布按整数倍放大（×2），关闭平滑，保持 LCD 的像素风格。
- **鼠标交互**：所有点击都转换成 LCD 物理坐标后发送 `click x y`，由**板端** hit map 解析并执行，所以 LCD 上也会同步出现反应（闪框、页签切换、选中高亮）。上位机**不单独维护一套状态**，避免两边不一致。只有悬停读数、右键菜单、滚轮这类纯显示操作在 PC 本地处理。
- **视图切换**：`[孪生视图]`（默认）和 `[分析视图]`（大号频谱、瀑布、遥测曲线，即原方案的布局），用 Tab 键切换。

### 4.2 音频功能（用户重点要求）
1. **PC 实时监听**：打开 `audio_stream on` 后，板端把**送往喇叭的同一份 PCM** 发到 PC，PC 用 `sounddevice` 播放，抖动缓冲 200 ms。板载喇叭和 PC 音箱可以分别静音（PC 本地静音不影响板子）。
2. **一键录音**：
   - 侧栏 `🔴 录音` 或 LCD 软按键 `[REC]`；
   - 保存为 `recordings/FM_95.80MHz_20261104_153012.wav`（48 kHz、16 bit、单声道）；
   - 同时生成 `.json` 附注：电台频率、LO、开始/结束时间、质量门控统计（静音时长、导频突出度最小/平均值）、丢包数、SHA256；
   - 可选导出 MP3（PC 上有 `ffmpeg` 时启用，没有就隐藏按钮）。
3. **板端双保险**：录音同时触发板端 `--record-audio`，网络丢包时可以用 `get_file` 取回板端的完整 WAV 校对。
4. **录音库**：侧栏列出已存录音，可以双击试听、显示波形和频谱图（语谱图 PNG 可导出给报告用）。
5. **音频与画面同步标记**：录音开始和结束时向事件日志写一条，回放会话时也能听到当时的录音。

### 4.3 其他丰富内容（提升展示和评分）
| 功能 | 说明 | 展示价值 |
|---|---|---|
| IQ 录制与导出 | 右键目标 → "录 IQ 5 s"，下载 `.cf32` + `.json`（中心频率、采样率 480 kSPS、调制识别结果），可直接导入 GNU Radio/Inspectrum/MATLAB | 体现"数据采集终端"价值 |

| 频段占用度 + 告警 | 统计各频点最近 N 秒的检出比例，显示在瀑布下方色带；YAML 告警规则（频段 + 功率），触发时弹窗、事件日志、LCD 事件区同步 | 体现"频谱监测"应用 |

**安全边界（不变）**：上位机**没有任何发射相关的按钮或命令**；B 组发射只能在板端终端输入 `yes` 后启动，上位机只能观看。音量、频率、录 IQ 时长都由板端再次夹紧，上位机传什么都不能越界。

### 4.4 开发方式
1. `tools/host/fake_board.py`：用合成数据或 `.zsr` 模拟 hostlink（包括 `ui_frame`、`pl_frame`、`audio`、`click` 的 hit map 响应），先离线完成全部界面和测试。
2. **孪生一致性自动测试**：在 PC 上用板端同一套 `ui_v3` 代码生成 `pack_ui` 字，经过协议传输后由上位机解包，与直接渲染的结果逐像素比对，必须 0 差异。
3. 再连真板验证。
4. **打包**：PyInstaller one-folder，输出 `dist/SentinelHost/SentinelHost.exe`，内置 A 组和 B 组示例会话各一段（≤ 50 MB，带一段 FM 录音），没装 Python 的电脑也能打开回放。

### 4.5 指标

| 指标 | 目标 |
|---|---|
| PS 区孪生一致性 | 自动测试逐像素 0 差异；真板上随机抽 20 帧 `ui_frame`，与板端同一 epoch 写入 BRAM 的字（读回）完全相同 |
| PL 区视觉一致 | 同一 `pl_frame` 下，上位机画面与黄金模型输出逐像素一致；与 LCD 实拍对比，坐标刻度和调色板一致（👤 目视） |
| 点击响应 | 点击到 LCD 和上位机都出现反应，中位 ≤ 200 ms，P95 ≤ 400 ms |
| 实时显示 | 孪生画布 ≥ 10 fps；PC CPU ≤ 25% |
| PC 实时监听 | 连续 10 分钟无明显断音；丢包 ≤ 0.1%；端到端音频延迟 ≤ 500 ms |
| 录音 | WAV 时长与实际时长误差 ≤ 0.1 s；与板端同时段 WAV 对齐后的样本一致率 ≥ 99.9% |
| IQ 导出 | `.cf32` 在 numpy 中重新读入，频谱峰值与上位机显示一致（误差 ≤ 1 bin） |
| 回放 | 目标表、事件、声音与录制时一致（自动比对） |
| 连续运行 | 30 分钟，内存增长 < 50 MB，无异常 |
| 测试 | `tools/host/tests/`：协议、孪生解包、hit map、音频缓冲与 WAV、录制回放一致性、占用度、fake_board 端到端，全部通过 |
| exe | 干净目录解压后能启动并回放内置会话（含声音） |
| 👤 目视/听音 | 用户确认孪生画面与 LCD 一致、点击联动、PC 能听到 FM、录音文件能正常播放 |

### 4. 音频面板：必须先说清楚的限制
G1 已经确认：**冻结位流没有播放 PCM 的读回口**，PL 解调后直接送 I2S，PS 拿不到喇叭实际播放的那份 PCM。因此：
1. **方案 A（本阶段实施，不改位流）**：PS 用 ADI RX DMA 读取**连续**的原始 IQ（3.84 MSPS），在 PS 上做 FM 软件解调（Y3 已验证 NumPy 解调速度达到实时的 1.5 倍以上），产生一路"PS 并行解调音频"，推给上位机做监听和录音。
   - 前提：先测试连续 DMA 是否无缺口（10 分钟，样本计数连续）。有缺口就记录缺口数，WAV 中插入静音并在附注里写明。
   - 界面和录音附注都标注"PS 并行解调（与喇叭同一射频输入、独立解调）"，**不能写成"喇叭播放的同一份 PCM"**。
   - 占用评估：PS CPU 增加量 ≤ 35%，LCD 帧率下降 ≤ 2 fps，喇叭零下溢不变；达不到时，音频流只在"音频"页面打开时才启用。
2. **方案 B（G6 类改位流，默认不做）**：在 PL 的音频 FIFO 前加一个 PCM 镜像 FIFO 加 DMA。必须由用户书面同意，并与 G6 一起做。
3. G3 协议中的 `audio` 消息增加字段 `source: ps_parallel_demod | pl_playback_mirror`，上位机按这个字段显示标注。
