## Y1 RF 带宽 3 MHz 复测（可选，仅 1 次）

**天线**：A。RX1A 接用户最终选定的 20–512 MHz 天线（STATUS 中记录为"新天线"）；TX1A 空。
**原因**：95.8 MHz 相对 LO（96.4 MHz）偏移 −600 kHz，而 RF 滤波带宽只有 1.5 MHz（±750 kHz），信号正好落在滤波器的滚降区。
**操作**：使用 sentinel_v1b，不重新构建，只改软件参数 `rf_bandwidth = 3 MHz`（AD9361 RX 模拟滤波器）。LO 96.4 MHz、3.84 MSPS，测 120 秒；同一参数下再测 98 MHz 120 秒，看容量告警。
**指标**：95.8 MHz 检出率 ≥ 80%，且 98 MHz 容量告警 < 5%。
**结果处理**：达标的话，把 X1 的备注改为"Y1 以 RF 带宽 3 MHz 达标"，X1 状态可以改为 DONE，并注明"参数修正，非 RTL 修改"；不达标就保持 FAIL，不再尝试。以后**默认 RF 带宽一律用 3 MHz**。
**提交**：`[Y1] RF bandwidth 3MHz retest`

## Y2 完成 X5：信道化捕获 + 识别上屏（必需）

**天线**：A
**前置条件**：v1d 的 PFB 第 3 轮仿真结果（STATUS 中注明"仍在运行"），先读取它的结论。
**操作**：
1. **PFB 仿真**：
   - 如果第 3 轮已经 PASS，继续往下；
   - 如果 FAIL 或没有结果：先查清原因，修复后最多再跑 1 轮（这算 Y2 的第 1 轮）；仍失败就走**降级方案 Y2-L**：不用 PFB，在 PS 端对 ADI RX DMA 的原始 IQ（3.84 MSPS）做 NumPy 数字下变频（DDC）、低通滤波，抽取到 480 kSPS，取 4096 点。识别器的输入格式不变。
2. **整机构建**（PFB 通过时）：v1d = v1b + PFB + NCO 捕获 + 捕获 DMA。时序必须 WNS ≥ 0、WHS ≥ 0，失败最多 3 轮；3 轮仍失败就走 Y2-L。
3. **调度与识别**：
   - 按 CFAR 目标轮询，新目标优先；每个目标最近 5 次识别结果投票；
   - 识别器使用 `src/ps/models/weights/amc_v2/selected.json` 指向的模型（X4 第 3 轮）；
   - 置信度 < 0.5 时显示"?"。
4. **UI**：
   - 列表每行显示：频率 / 带宽 / 功率 / **调制类型** / 置信度；
   - 右侧显示当前选中目标的**星座图**（200×200，由 PS 绘制到 UI 层）；
   - 状态栏显示"识别时延"（目标第一次出现到第一次给出识别结果的时间）。
5. **板端运行**：LO 96.4 MHz（或 98 MHz），3.84 MSPS，运行 120 秒。

**指标**：

| 指标 | 目标 | 说明 |
|---|---|---|
| PFB / NCO 仿真 | 逐位一致 | 走 Y2-L 降级方案时写"不适用" |
| 整机时序 | WNS ≥ 0、WHS ≥ 0 | 走 Y2-L 时不涉及 |
| FM 电台被识别为 FM 的比例 | ≥ 80%（按 5 票投票之后的结果统计） | 以 95.45 MHz 和 95.8 MHz 两个已知电台统计 |
| 识别时延中位数 | ≤ 1 s | 包括捕获、DMA、推理和投票 |
| 显示帧率 | ≥ 30 fps | 识别不能拖慢 PL 显示 |
| 采样 FIFO 溢出 | 0 | — |

**👤 验收**：用户确认屏幕列表中 FM 电台标为"FM"，星座图区域在变化（FM 的星座图是一个圆环）。
**提交**：`[Y2] channel capture and on-screen AMC (v1d or PS fallback)`

## Y3 FM 实时监听（必需，输出到板载喇叭，见 Z7）

**天线**：A。音频由底板已焊好的J36喇叭输出；不需要外接喇叭，耳机不再单独开发和验收。先核实音频通路，再做Z7规定的1kHz正弦3秒出声测试，等待人工听音确认。该测试不需要启动射频。
**操作**：
1. **方案 Y3-P（优先，PL 实现）**：
   - 在 v1d 上增加 `fm_demod`：对选中信道的 480 kSPS IQ 做 CORDIC 鉴相 → 75 µs 去加重 → 抽取到 48 kHz；然后经 `i2s_tx`（24 位，左右声道复制同一路信号）输出；
   - I2S 引脚：`aud_mclk` U9（12.288 MHz，由 MMCM 从 50 MHz 生成）、`aud_bclk` AA11、`aud_lrc` U6、`aud_dacdat` AB11，全部 LVCMOS33；
   - 这个改动需要重新构建，时序最多 3 轮。
2. **方案 Y3-S（降级，PS 软件实现）**：
   - PL 只加一个 `i2s_tx` 和一个 AXI-Stream FIFO（8 KiB）；
   - PS 用 NumPy 对 Y2 的捕获数据（或 RX DMA 的原始数据）做 FM 解调，通过 Xilinx AXI DMA 推流到 I2S；
   - 要求 PS 处理速度 ≥ 实时速度的 1.5 倍。
3. **ES8388 初始化**（两种方案相同）：
   - 通过 AXI IIC 访问，SCL = A18、SDA = A19（Bank35，LVCMOS33，上拉），7 位器件地址 **0x10**；
   - 初始化序列参考正点原子 `vendor/atk/pynq_ref/ip_repo/audio_codec_ctrl_v1.0`（读它的 HDL 或驱动中的寄存器表），以及 ES8388 数据手册；
   - 按Z7打开DAC、LOUT2/ROUT2及OUT1，单声道左右复制，喇叭使用ROUT2；退出时数字静音并关闭所有输出；
   - 初始音量约−20dB，软件提供`--volume`参数；按芯片支持的档位选择保守相近值并记录实际值。仍插在P1的耳机先不要佩戴。
4. `monitor.py --listen 95.8e6`：自动把 LO 设在 96.4 MHz，选中对应信道和 NCO 频率，开始播放。

**指标**：

| 指标 | 目标 |
|---|---|
| 连续播放 | 5 分钟，I2S FIFO 下溢次数 = 0 |
| 导频突出度（19 kHz，可选） | ≥ 25 dB |
| 主观音质 | 👤 "能清楚听到人声，只有轻微底噪" |
| 屏幕帧率 | 播放期间 ≥ 30 fps |

**👤 验收**：先由用户确认1kHz/3秒测试音，再确认板载喇叭连续播放5分钟、能听清广播。保留FIFO下溢为0和播放期间屏幕≥30fps的量化门禁。
**提交**：`[Y3] real-time FM audio on onboard speaker (PL or PS)`

## Y4 空口闭环 + 数字注噪评测（G3，必需）

**天线**：**配置 B**（首选）：TX1A 和 RX1A 各接一根 2.4 GHz 板状天线，相距 ≥ 30 cm；或者**配置 C**：两根 20–512 MHz 天线相距 ≥ 50 cm，工作在 433.92 MHz。详见 `docs/antenna_sd_guide.md`。
**前置条件**：Y2 完成；N1 的 TxGuard 和 TX DMA 已就绪；src_mux 的 MODE = 3（注噪）已在 v1 系列位流中实现（需确认 v1b/v1d 中包含，否则按 Y2-L 的方式在 PS 端加噪声，并在报告中说明）。
**操作**：
1. 👤 用户按配置 B 接好天线并拉开距离，确认后才能开始；
2. `loopback_eval calibrate`：LO 2.45 GHz（配置 C 时为 433.92 MHz），TX 衰减从 89 dB 起每步减小 3 dB，直到 SNR ≥ 25 dB，或者到达 **30 dB 下限**；RSSI > −30 dBm 时立即中止并恢复 89.75 dB；
3. `loopback_eval sweep`：固定 TX 衰减，注噪 SNR 取 −4 到 20 dB（步长 2 dB），10 类调制 × 13 个 SNR 点 × 200 段；结果写入 `board/measurements/y4_ota_*.json`，并保存数据集 `data/captured/air_v1`；
4. **不重新训练**（X4 已经用完 3 轮）。只用 `air_v1` 评估模型在真实射频损伤下的表现，与仿真曲线对比；
5. Pfa：TX 关闭，在空闲频段（2.30–2.39 GHz，或 433 MHz 附近无信号时）统计 1e6 个 bin；
6. Pd：TX 发单音，扫描注噪 SNR（−6 到 16 dB，步长 1 dB），统计 CFAR 命中率；
7. 全程记录 TX 衰减的最小值，必须 ≥ 30 dB。

**指标**：

| 指标 | 目标 |
|---|---|
| 空口 10 类准确率 @ 注噪 SNR = 10 dB | ≥ 80%（与仿真曲线的差距 ≤ 10 个百分点） |
| 空口 8 个大类准确率 @ SNR = 10 dB | ≥ 90% |
| 实测 Pfa / 设定 Pfa | 0.5–2 |
| Pd @ 单 bin SNR = 10 dB | ≥ 90% |
| TX 衰减最小值 | ≥ 30 dB |
| 是否发生 RSSI 超限中止 | 记录（如果发生，拉开天线后重测） |

**提交**：`[Y4] G3 OTA loopback with digital noise injection`。G3 标为 DONE。

### Z7 音频输出：板载喇叭（2026-11-03 用户确认，取代耳机方案）
- 底板 J36 位置**已焊有一个圆形喇叭**（丝印 SPEAKER，FMC 座下方），由 ES8388 的 ROUT2 → 板载功放 MD8002A（U25，5V，常开）驱动。**不需要购买喇叭**，软件打开 OUT2 即可出声。
- 软件：ES8388 打开 DAC 和 **LOUT2/ROUT2**；单声道解调结果**左右声道复制**（功放只接右声道）；`--volume` 可调，初始约 −20 dB。OUT1（耳机）初始化时一并打开，但**不再单独开发或验收耳机**。
- 先做一次"出声测试"（Y3 第一步）：PS 通过 I2S 播放 1 kHz 正弦 3 秒，👤 用户确认喇叭有声音。没声音时依次排查：ES8388 I2C 应答（地址 0x10）→ OUT2 使能和音量寄存器 → I2S 时钟（MCLK 12.288 MHz）→ 功放供电。
- 板载小喇叭音量有限，演示时手机靠近录音；同时用 `--record-audio` 在板端保存 WAV，后期选用效果较好的一路。
- Y3 验收改为：喇叭连续播放 5 分钟无断音，👤 用户确认"能听清广播"。

### Z10 时序收敛策略（2026-11-03，**下一次整机构建前必须执行**）
详见 `docs/timing_closure_strategy.md`。执行顺序：
1. **T2 + T3**（只改构建脚本，不改设计）：`ADI_MAX_OOC_JOBS=6`、`-jobs 6`、`maxThreads 8`；保留 OOC 缓存；只改实现时不重跑综合。
2. **T1**：新工程 `sentinel_v2_100m`，`dsp_clk` 从 150 MHz 改为 100 MHz；新增 `DSP_CLK_HZ` 参数，统一替换所有与时钟频率有关的软件常量；重跑与时钟相关的 testbench。
3. **T4**：修复 `adc_tap` 的复位跨时钟结构，以及 `cfar_core` 检测器的流水和扇出。
4. 用 `sentinel_v2_100m` 作为后续 Y2/Z2/Y3 的基线（Z2 新 UI 和 FM/I2S 都在这个基线上集成）。
- **验收**：WNS ≥ +1.0 ns、WHS ≥ 0；单音、三音、回放 8192 字零错；3.84 MSPS 下 SAMPLE_DROP = 0、显示 ≥ 30 fps；记录构建耗时，与之前对比。
- **轮次**：最多 3 轮。如果 100 MHz 仍不收敛，说明问题出在布局拥挤而不是时钟，再执行 T5（Pblock、减少 AXI 时钟转换器）。
- 禁止用 false_path 或 multicycle 掩盖违例。
