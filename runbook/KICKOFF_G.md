【本阶段目标】在不改位流的前提下提升演示效果：
G0 状态核对与 F3 SD 备份重试 → G1 演示运行时常驻化与连续 WAV → G2 LCD 界面 v3（四色约束内）→ G3 板端 hostlink 数据服务（孪生帧 ui_frame/pl_frame、click 点击映射、音频流、文件下载）与手机网页 → G4 PC 上位机 SentinelHost（主画面是与 LCD 一致、可以鼠标点击的孪生画面；加上 PC 实时监听、一键录音保存 WAV、IQ 录制导出、统计、会话录制回放、HTML 报告、演示模式、exe）→ G5 show 联动演示、replay 兜底与彩排 → 再按 G_showcase 第 3 节调整后的内容执行 F4 → F5 → F6。G6（调色板改位流）默认不做，除非我书面同意。

【本阶段原则】
- 基线固定为 board/overlay/sentinel_v2_100m（100 MHz，3.84 MSPS）。G0–G5 全部是软件工作：不重新综合或布线、不训练、不调 CFAR、不追 30.72 MSPS 或 WNS +1 ns。历史 FAIL 如实保留。
- PS 的 UI 只能写右侧 240×400 和底部 800×80 区域，调色板固定为黑/白/黄/青；用字号层级、反色块、闪烁和图形表达状态，不依赖红/绿。
- 板端只用 Python 3.8 标准库和已有的 numpy/PIL，不在板上安装新包；PC 上位机用 Python 3.12 + PySide6 + pyqtgraph，装在仓库 .venv 里。
- hostlink 不提供任何发射或 TX 衰减相关命令；命令只用白名单，音量（−30 到 −6 dB）、监听频率（87.5–108 MHz）、IQ 录制时长（≤ 10 s）由板端再次夹紧；不能阻塞采集、LCD 或喇叭音频；不把 token 或板子密码写进仓库文档。
- 上位机孪生一致性的做法：PS 区直接显示板端发来的 pack_ui 字（与写进 LCD 的是同一份数据），PL 区用 sim/golden/render.py 黄金模型重建；所有鼠标点击都转换成 LCD 坐标发 click，由板端 ui_v3 的 hit map 和唯一状态源执行，LCD 同步反应；上位机不单独维护一套界面状态。
- 音频：PC 监听和录音使用板端送往喇叭的同一份 PCM（48 kHz/16 bit/单声道）；录音同时保存 .json 附注和 SHA256，并用板端 WAV 校对。
- 先离线开发（fake_board、PNG 预览、单元测试），再上板验证。G2 的界面预览 PNG 先发给我确认风格。

【执行规则】
- 按 G0→G5→F4→F5→F6 顺序执行（G2 和 G3 可以并行开发）。每步：前置条件 → 执行（长任务放后台，日志写到 logs/G*.log）→ 对照 G_showcase 中的指标量化验收 → 更新 STATUS.md（新增 G 表）→ git commit "[Gn] ..."。每个子项最多 3 轮，未达标时如实记录后继续。
- 天线：G0–G4 和 G5 的 A 组用配置 A（RX1A 接 20–512 MHz 天线，TX1A 空）；G5 的 B 组用配置 B-直插（两根 2.4 GHz 折叠胶棒直接拧在 TX1A/RX1A 上，竖直同向，TX 衰减下限 40 dB）；F4 后半段用配置 D。每次换天线前先停止射频，告诉我怎么接，等我确认后再继续。只使用 RX1A/TX1A。
- 射频安全：没有衰减器；禁止用 SMA 线把 TX 和 RX 直接相连；TX 默认 89.75 dB；RSSI > −30 dBm 立即中止；只在 2400–2483.5 MHz 发射；结束后 TX 恢复 89.75 dB，ENSM 回到 ALERT。
- 常驻运行时不能省掉每段结束时的安全读回（GPIO/SRC/audio = 0、TX 衰减）；异常时先完整清理再跳过或退出。
