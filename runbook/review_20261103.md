## 2. 不足与改进建议（按优先级）

### 🔴 D1 工作区有未提交的改动
- 13 个已修改文件和 7 个测量 JSON 未提交（N4 收尾时按用户要求暂停）。
- **处理**：90_plan 的 X0 第一件事就是核对这些改动并提交。不能丢弃，因为这些改动就是 N4 板端验收所用的代码版本。

### 🔴 D2 处理带宽只验证到 3.84 MSPS（"处理带宽"是选题简介中明确写出的评价指标）
- 仿真结果显示，在反压条件下整条链只能做到约 29.889 MSPS，原因是 CFAR 按帧串行处理，会反压 `spec_front`，所以 30.72 MSPS 理论上就不可能做到零溢出。
- **处理**（90_plan X2）：
  1. 把 CFAR 改为乒乓双缓冲，与 FFT 帧流水并行，保证主链永远不反压 ADC；
  2. 依次实测 7.68 / 15.36 / 24.576 / 30.72 MSPS，每档跑 10 分钟，overflow 必须为 0；
  3. 达不到 30.72 时，如实以"最高零溢出档位"作为指标。

### 🟠 D3 目标列表容量告警频繁（约 40% 的帧超过 32 个目标）
- 原因：FM 频段内电台多，频谱上还有梳状杂散，CFAR 在一个宽信号上切出多个窄段。
- **处理**（X1）：
  1. 在聚类后增加"最小宽度 / 合并间隙"参数（例如 gap 从 2 增大到 8 个 bin，宽度小于 2 bin 的段丢弃）；
  2. 增大 Welch 平均系数；
  3. DC 附近和已知梳状杂散位置加入可配置屏蔽表；
  4. 状态寄存器与目标快照改为同一帧锁存。
- **指标**：98 MHz 下告警率 < 5%，同时 FM 电台的检出率不下降（与 N4 的结果对比）。

### 🟠 D4 SD 卡与断电导致的数据损坏风险（已经实际发生过）
- N1 期间出现过：启动失败（REBOOT_STATUS 0x200A，即"SD 启动镜像查找失败"）、ext4 日志恢复、FAT 非正常卸载告警、Windows 报告卷健康"Warning"；还有一轮测试因中途按复位，**NPZ 文件变成 0 字节**。
- **处理**：
  1. 软件侧已经改为 fsync + 原子替换写入，这一点要保持；
  2. 每次断电前执行 `sudo sync && sudo shutdown -h now`；
  3. **立即做一次整卡备份**，并准备一张备用卡；
  4. 操作流程见 `docs/antenna_sd_guide.md` 第 3 节。

### 🟡 D5 默认参数不一致
- RTL 复位默认值和板端管理入口的默认 `BUS_PHASE` 仍是 25，但已验收的工作档是 3。
- **处理**：板端程序默认改为 3（RTL 复位值可以保留 25 作为安全上电值，由软件在初始化时写入 3）。

### 🟡 D6 路径与交接信息混乱
- 交接文档写的是 `D:/FPGA/ZSS/zss`，N4 汇总写的是 `F:/.zss/zss`，两者不一致。
- **处理**：AGENTS.md 明确"仓库根目录 = 当前工作目录，不写死路径"；`report/HANDOFF_*` 和 `NEXT_AGENT_PROMPT.md` 中写死的路径改为相对说明。

### 🟡 D7 调制识别仍然缺失
- P2.9 失败，N6（分层识别 + 盲同步）尚未开始。目前屏幕上的信号列表只有频率、带宽和功率，没有调制类型。这是选题简介中的核心功能之一。
- **处理**：放在 X4。

### 🟡 D8 ADI 内部的 Critical CDC 和 IO 约束告警
- 这些属于 ADI IP 自带的告警，不影响功能。
- **处理**：报告中逐条解释来源（ADI 核内同步器、异步复位等），不要回避。
