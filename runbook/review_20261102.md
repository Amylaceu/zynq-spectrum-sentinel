## 3. 问题与改进建议（按优先级）

### 🔴 R1：PL 侧处理链完全缺失（影响"创新性"30 分 + "性能与资源优化"20 分）
- 现状：频谱由 Cortex-A9 用 NumPy 对 65536 点快照计算，属于"纯软件 SDR + FPGA 当搬运工"。评委对 FPGA 赛道最看重的硬件加速、资源和时序优化、加速比，目前全部没有。
- 建议：**立即转入 PL 主链**（`80_next.md` 中的 N2–N4）。先做 `spec_front`（加窗 → FFT → 功率 → Welch → dB）+ `cfar_core`，直接替换 CPU 计算频谱，并对照现有 CPU 实现给出 E1 加速比。这是性价比最高的一步。

### 🔴 R2：runbook 的显示设计与实际硬件不符
- 实际屏幕为 **ATK-MD0700 V2.4，SSD1963 控制器，8080 16 位并口，800×480，接 J22**（以及摄像头排针 P3 的引脚），而 runbook 30/40/50/60 仍按 J26 RGB 屏 + VDMA + v_tc + rgb2lcd + GT9147 编写。
- 后果：P3.6（显示引擎）、P4.3（约束）、P4.4.3（显示集成）如果照原文执行，会做出与硬件不匹配的设计。
- 建议：以 `80_next.md` 第 2 节的"显示架构修订"为准，原 P3.6 / P4.3 中关于 J26 的内容作废。

### 🔴 R3：屏幕刷新率 1.67 fps 的瓶颈在 8080 总线时序，不在 CPU
- `lcd_j22_framebuffer.v` 中 `BUS_PHASE_CYCLES=25`（50 MHz），每个像素约 77 个时钟周期，约 1.54 µs；800×480 = 384 000 像素，**仅写一帧就需要约 0.59 s**，上限约 1.7 fps，与实测吻合。
- 建议：
  1. 逐步降低 `BUS_PHASE_CYCLES`（25 → 8 → 4 → 3），每档实测画面是否出现错点。考虑到彩色杜邦线长度和信号完整性，不要一步降到最小；
  2. **局部刷新**：只重写频谱区，瀑布图使用 SSD1963 的硬件垂直滚动（命令 `0x33 set_scroll_area`、`0x37 set_scroll_start`），每帧只写一行；
  3. 目标：频谱区 ≥ 15 fps、瀑布图每帧 1 行（优化前后对比可作为实验 E10 的新内容）。估算：只刷 560×160 的频谱区，P = 25 时约 7 fps，P = 8 时约 20 fps。

### 🟠 R4：调制识别（P2.9）失败原因明确，需要换方法而不是继续调参
- 混淆矩阵显示：BPSK / 2FSK / GFSK / OOK / AM / FM 的召回率在 0.82–0.97 之间；**QPSK↔8PSK（0.37/0.32）和 16QAM↔64QAM（0.38/0.51）几乎是随机猜**。
- 原因：1024 点、4–16 点/符号、随机频偏和多径条件下，没有载波和定时同步，网络无法分辨同族调制的阶数。这是 AMC 领域的已知难点，不是训练次数不够。
- 建议（`80_next.md` N6）：**分层识别 + 盲同步**。第一层用 CNN 区分 7 个大类（已经表现良好）；第二层对 PSK 族和 QAM 族做盲符号率估计 → 四次方频偏校正 → Gardner 定时恢复 → 在 1 点/符号的星座上计算 C40/C42/幅度直方图，以此判断阶数。同时把捕获长度增加到 4096 点。阈值 88% 保持不变；新方法作为 P2.9b 计数（最多 3 轮），仍不达标时如实报告，由用户决定。

### 🟠 R5：FM 监听目前是"离线 WAV"，不是实时耳机输出
- 建议：在 PL 中实现 FM 解调和 I2S（`demod_audio`），PS 用 I2C 配置 ES8388，耳机插 LINE_OUT（P1）。音频引脚 U9/AA11/U6/AB11/U5（Bank13）和 I2C A18/A19（Bank35）与 J22 / P3 显示引脚**无冲突**（已核对 `lcd_j22.xdc`）。

### 🟡 R6：BRAM 预算需要重算
- `live_z20_lcd` 的 256 KiB 双页帧缓存已占 **68/140** 个 BRAM。原计划的 FFT 2048（约 14）、CFAR、PFB（约 8）、HOC、余辉图（12）、FIFO 加起来可能超过上限。
- 建议：帧缓存改为单页加局部刷新（RGB332 400×240 = 96 KiB），或者把瀑布图交给 SSD1963 自己的显存（硬件滚动）。余辉图（DPX）降为 P2 优先级。

### 🟡 R7：状态与文档的一致性
- G0 的信息已经齐全（屏幕型号、跳线 2.5V、天线类型），但状态仍为 TODO，应补记为 DONE。
- `AGENTS.md` 第 2 节和 `docs/hardware_bom.md` 中的屏幕信息需要更新为 J22 SSD1963。
- `src/ps/models/weights/` 有未跟踪文件，需要决定提交或忽略：失败模型的权重建议只保留 metrics，`.pt` 不入库。
- `board/scripts/` 中已有多个独立脚本（`capture_*`、`run_*`），出现了重复的 ctypes 声明（每个脚本都重复写 `lib.z20_get_tx_attenuation.argtypes=...`）。建议在 P5 收敛为 `sentinel.rf.ad9361` 一个封装，并补上 `TxGuard`（runbook P5.3 的要求，目前代码中尚无 `TxGuard`）。

### 🟡 R8：TX 方向尚未验证
- TX-DMA → BIST 数字回环 → RX 逐位比对是 G2 的必选项，也是后续空口闭环（G3）的前提，应尽快补上。整个过程不经过射频，不需要衰减器。
