# H 方案：快速全景扫描 + 上位机现场讲解控制台 + 无线电扩展（2026-11-04 起）

> 阅读顺序：`AGENTS.md` → `runbook/CONTEXT.md` → `runbook/G_showcase.md` → **本文件** → `docs/antenna_sd_guide.md`。
> 本文件**取代 G5 中的"彩排"要求**，并修改 F4 的扫描实现方式。其他安全规则和冻结规则不变。
> 基线不变：`sentinel_v2_100m`，不重新综合或布线。H 阶段全部是 PS 和上位机软件工作。

## 0. 背景（用户 2026-11-04 提出的三个问题）
1. **全景扫描太慢**：F4 离线方案以 8 MHz 步进规划了 55 + 274 = 329 个 LO（每段有效 20 MHz，相邻段重叠 12 MHz），而且计划每段保存原始 IQ，**还没有真板实测耗时**。
2. **不想彩排**：用户希望在现场用上位机**一段一段手动点击**，边讲边展示，由用户自己掌握节奏。
3. **想增加 WiFi 或其他无线电功能**。

## H1 快速全景扫描（必需，并入 F4）

### 1.1 先实测，再优化
第一步只扫配置 A 的 10 个 LO，记录**每个 LO 的耗时分解**，写入 `board/measurements/h1_timing_r1.json`：
- 采样率切换（3.84 → 30.72 MSPS，整次扫描只做一次）；
- LO 调谐和锁定（含 VCO 校准）；
- AGC 稳定等待；
- DMA 采集；
- Welch 计算；
- 写文件；
- Python 调度开销。

不能只凭估计判断瓶颈，要以实测分解为依据。

### 1.2 优化手段（按预期收益排序，逐项实测效果）
| 编号 | 手段 | 预期 |
|---|---|---|
| S1 | **加大步进**：有效带宽 20 MHz，只需要盖住 LO 附近 ±150 kHz 的屏蔽区和通带边沿，步进从 8 MHz 改为 **18 MHz**（重叠 2 MHz）。段数从 329 降到约 150。覆盖检查必须保持"无缺口"（沿用 `panorama.py` 的覆盖检查） | 段数减少约 55% |
| S2 | **不按段保存原始 IQ**：每段只保存 4096 点 PSD（float32，16 KB）和元数据；原始 IQ 只在 `--keep-iq` 时保存，或者只保存功率最强的 5 段 | 去掉 SD 写入瓶颈 |
| S3 | **固定增益**：扫描时 AGC 改为手动增益（按频段分 2–3 档，从配置读取），不再等待 AGC 稳定；在元数据中记录增益 | 每段省掉 AGC 等待 |
| S4 | **减少采样点**：每段 64k 点（2.1 ms），Welch 4096 点、50% 重叠，平均约 31 次 | 采集和计算都缩短 |
| S5 | **流水线**：第 N 段计算 PSD 时，第 N+1 段已经开始调谐和采集（双缓冲；DMA 所有权规则沿用 `rx_queue.py`） | 计算时间被隐藏 |
| S6 | **AD9361 fastlock**（可选）：如果 libad9361 的 fastlock 存取接口可用，对常用的 LO 预先存储 profile，跳过 VCO 校准。只有在 1.1 的分解显示调谐时间占比 > 30% 时才做 | 调谐时间减少 |

### 1.3 扫描模式
| 模式 | 范围 | 用途 | 目标耗时 |
|---|---|---|---|
| **快扫预设** `quick` | FM 88–108、对讲机 400–470、433 ISM、GSM900、1.8 GHz、2.4 GHz ISM，每个频段 1–2 段 | 现场讲解（一键出图） | **≤ 5 s** |
| **配置 A 全扫** | 70–512 MHz | 正式全景 | **≤ 10 s** |
| **配置 D 全扫** | 512 MHz–2.7 GHz | 正式全景 | **≤ 30 s** |
| **巡航** `cruise` | 任选范围，循环扫描 | 上位机背景页，持续更新 | 每轮同上 |

以上目标在 1.1 实测后可以修正一次，修正理由写进 STATUS。达不到的话如实记录。

### 1.4 展示
- 上位机"全景"页：**每扫完一段就立即画上去**（从左往右逐段填充，用新消息 `pano_tile`）。观众看到的是一张逐渐"长出来"的全景图，不用盯着进度条干等。
- 已知频段在图上标注（FM、对讲、433、GSM、LTE、WiFi），单击某个频段就跳到该 LO（发 `set_lo`），回到 3.84 MSPS 实时监测和识别——"**先全景发现，再定点识别**"，这是讲解的主线。
- 扫描结束后**必须**恢复 3.84 MSPS、原 RF 带宽、原 LO 和 AGC，并读回检查；TX 全程 89.75 dB。

### 1.5 关于换天线
配置 A（20–512 MHz 天线）和配置 D（宽带胶棒天线）的低频段和高频段仍然需要分开扫。**现场讲解时**：如果宽带胶棒的标签覆盖 700 MHz 以下，就只用 D 天线做一次 70 MHz–2.7 GHz 的完整扫描（低频段灵敏度会差一些，图上注明"单天线快速全景"），省去现场换天线。正式全景图（报告用）仍然分 A、D 两次扫描。

**H1 指标**：耗时分解已记录；配置 A ≤ 10 s、配置 D ≤ 30 s、快扫 ≤ 5 s（或已记录的修正值）；覆盖无缺口；扫描前后 DMA 无溢出、恢复状态读回全部正确；上位机逐段显示正常。
**提交**：`[H1] fast panorama with timing breakdown and live tiles`

## H2 上位机现场讲解控制台（必需，取代 G5 彩排）

### 2.1 思路
用户在答辩现场用上位机**一个场景一个场景地点**，讲完一段再点下一段。没有倒计时，节奏由用户掌握。板端常驻运行时（G1 的 `runtime_v2`）进入"**服务模式**"，等待上位机下达场景指令。

### 2.2 板端：服务模式
- 启动：`sudo sh scripts/sentinel.sh serve`（只接收）或 `sudo sh scripts/sentinel.sh serve --arm-ota`（允许空口场景，见 2.4）。
- 位流、模型、ES8388 都只加载和初始化一次，之后一直常驻。
- 新命令 `scene <名称>`（白名单）。每个场景就是现有 demo 段的"无时长版本"：一直运行，直到下一个场景、`idle` 或 `stop`。
- **接收场景之间切换**：不再整体复位射频，只改 LO、信号源和模式，每次切换都读回 TX 衰减 = 89.75 dB 和 SRC 状态。目标切换时间 **≤ 2 s**（G1 中每段都复位导致约 4.7 s）。只有进出空口场景、`stop` 和异常时才走完整清理。

### 2.3 场景列表（上位机"讲解"页面的按钮）
| 编号 | 场景 | 天线 | 内容 | 上位机自动切到的页面 |
|---|---|---|---|---|
| 0 | 预检 | 当前 | 一键检查：位流哈希、AD9361 ID、TX 89.75 dB、温度、导频质量、网络延迟、上位机录制空间；**全绿才建议开始讲** | 系统 |
| 1 | 系统介绍 | — | 不动射频，只显示架构框图、资源、时序 | 系统 |
| 2 | 快速全景 | A 或 D | H1 快扫，逐段长出全景图 | 全景 |
| 3 | FM 监测与识别 | A | LO 96.05 MHz，频谱、瀑布、目标列表、识别、星座图 | 识别 |
| 4 | 锁台监听 | A | 自动选最强的可信 FM 电台，喇叭出声（用户也可以在列表中双击换台） | 音频 |
| 5 | 测试源三音 | — | `--source test`，显示频点误差，证明 FPGA 处理精度 | 监测 |
| 6 | 2.4 GHz 态势 | D 或 B 的 RX | TX 关闭，WiFi/蓝牙态势（H3b） | 全景 / ISM |
| 7 | 空口闭环识别 | **B-直插** | 10 类调制依次发送，"发送 → 识别"实时显示，混淆矩阵 | 闭环评测 |
| 8 | 注噪鲁棒性 | **B-直插** | 固定 QPSK，用滑块调注噪幅度，实时看准确率变化 | 闭环评测 |
| 9 | 空口数据链 | **B-直插** | H3c：输入一句话或选一张小图，发送、识别、解调、上屏 | 数据链 |
| 10 | 性能面板 | — | 帧率、吞吐、PL 与 CPU 对比 | 系统 |

- 每个按钮显示状态：可用 / 需要换天线 / 功能未完成（灰色，悬停显示原因）。
- **演讲者备注**：每个场景附 3–5 条讲解要点（`tools/host/scenes.yaml`，用户可以自己改）。上位机可以**双窗口**：投影窗口只显示孪生画面和数据面板；笔记本屏幕显示控制台和备注。
- **快捷键**：`→` 下一个场景，`←` 上一个场景，`Space` 暂停或继续，`Esc` **立即停止**（所有场景都有效）。
- 每次讲解自动录成 `.zsr` 会话，结束后一键导出 HTML 报告。

### 2.4 空口场景由上位机启动的安全设计（修改原"上位机不能发射"规则）
用户希望全程在上位机上操作，所以允许上位机**启动预设的空口场景**，但必须满足**全部**条件：
1. **板端物理确认**：只有在开发板 SSH 终端以 `serve --arm-ota` 启动、并输入 `yes` 确认"配置 B-直插已接好"之后，空口场景才可用。没有 arm 时，上位机上这些按钮是灰色的。arm 状态在重启或 `stop` 后失效。
2. **只能选预设场景**：上位机**不能**设置 TX 衰减、频率或任意波形。发射频率固定 2.45 GHz，TX 衰减由板端在 40–89.75 dB 内自动爬升（沿用 F3 逻辑），注噪滑块只控制数字注噪幅度，不控制射频功率。
3. **上位机二次确认**：点击空口场景时弹出红色确认框（显示天线配置示意图），点"确认发射"才执行。
4. **心跳看门狗**：发射期间上位机每 0.5 s 发一次心跳，板端 **2 s** 收不到就立即停止发射（衰减恢复 89.75 dB，ENSM 回到 ALERT）。网线断了也会自动停。
5. **单次时长上限**：每次空口场景最多 120 s，到时自动停止；再发要重新点。
6. 其余规则不变：RSSI > −30 dBm 立即中止；TxGuard 硬下限；只在 ISM 频段；退出时全部读回。
7. 上位机顶栏在发射期间显示**红色闪烁**的"TX ON 2.45 GHz 52 dB"，LCD 上显示黄色闪烁块。

### 2.5 关于"不彩排"
可以不做 G5 原定的连续 3 遍彩排，改为本节的**功能验收**：每个场景通过上位机单独执行 1 次，再按 0→10 的顺序完整点 1 遍。这是在验证功能，不算彩排。
**建议用户在答辩前至少自己完整点一遍**，主要是熟悉换天线的时机：场景 6–9 需要配置 B 或 D，换天线时先点 `idle`。

**H2 指标**：
| 指标 | 目标 |
|---|---|
| 场景启动（从点击到画面就绪） | 接收场景之间 ≤ 2 s；进入空口场景 ≤ 8 s（含衰减爬升） |
| 场景连续切换 | 0→10 完整点 2 遍（空口场景在 B-直插下），无崩溃，每次切换的读回检查全部通过 |
| Esc 停止 | 从按下到 TX 衰减读回 89.75 dB ≤ 1 s |
| 心跳看门狗 | 发射时拔网线，≤ 2.5 s 内停止发射（真板测试 3 次） |
| 未 arm 时空口命令 | 100% 拒绝 |
| 预检 | 人为制造 3 种故障（拔天线导致导频质量差、断网、位流不符），都能报出来 |
| 👤 确认 | 用户亲自点一遍，确认操作顺手 |

**提交**：`[H2] host presenter console with scene control and OTA arming safeguards`

## H3 无线电扩展

### H3a 无线连接（强烈建议，0.5 h）
- Z20 板上没有 WiFi。最简单可靠的做法：买一个**便携路由器**（如 GL.iNet GL-MT300N-V2 / GL-SFT1200，约 100–200 元，USB 供电）。开发板用网线接路由器 LAN 口，上位机笔记本和手机连路由器的 WiFi。
- 路由器 LAN 网段设成 192.168.2.x，开发板 IP 保持 192.168.2.99 不变（或者在路由器上做 DHCP 绑定），**代码零修改**。
- 效果：答辩时笔记本可以离开开发板，到投影仪旁边操作；评委可以用手机扫码打开 `http://192.168.2.99:8080` 看实时频谱。上位机顶栏增加"二维码"按钮，显示网页地址的二维码。
- 不建议用 USB WiFi 网卡插开发板：PYNQ 镜像的驱动兼容性不可控，还要占用 CPU 和 USB 口。
- **注意**：路由器的 WiFi 本身就在 2.4 GHz 上发射，演示 2.4 GHz 态势和空口闭环时会出现在频谱中。建议把路由器设为 **5 GHz WiFi**，或者把 2.4 GHz 固定在信道 1 或 13，避开空口闭环的 2.45 GHz（信道 8–9 附近），并在讲解中把它当作"已知 WiFi 信号"指出来。

### H3b 2.4 GHz ISM 态势（建议，1 天）
- 原理：用 H1 的 30.72 MSPS 快照覆盖 2400–2483.5 MHz（5 段），每段连续采集多个短快照（例如 20 次 × 2 ms），只在 PS 上做能量检测，**不解调 WiFi 或蓝牙内容**。
- 输出：
  - **WiFi 信道占用率**：信道 1–13 每个信道的时间占用百分比（柱状图），按约 20 MHz 宽的突发识别为"WiFi 类"；
  - **蓝牙/跳频检测**：约 1–2 MHz 宽、几百微秒到几毫秒的短突发，频点不断变化 → 标为"跳频类（疑似蓝牙）"，画出"时间 × 频率"跳频点图；
  - **突发统计**：每类信号的突发时长分布、占空比；
  - 微波炉之类的宽带干扰按"宽带连续"单独归类。
- 这些是基于带宽和时长特征的**粗分类**，上位机和报告都标注"能量特征分类，未解码协议"。
- 展示：上位机新增"ISM"页（WiFi 信道柱状图 + 跳频点图）；场景 6 使用这一页。用手机开热点或打开蓝牙音箱，就能现场看到信道占用变化，互动效果好。
- **指标**：5 段扫描 + 统计 ≤ 3 s 刷新一次；用手机热点（已知信道）验证：对应信道占用率明显高于其他信道（≥ 3 倍）；用蓝牙设备验证出现跳频点。

### H3c 空口数据链（建议，展示效果最强，2 天）
- **内容**：上位机输入一句话（≤ 64 字节）或选一张 32×32 的小图 → 板端打包（前导码 + 同步字 + 长度 + 数据 + CRC16）→ 用选定的调制（GFSK / BPSK / QPSK）通过 TX1A 循环发送 → RX1A 接收 → **先用 AMC 识别调制类型** → 按识别结果选解调器 → 解调、CRC 校验 → LCD 和上位机显示收到的文字或图片，同时显示误码、CRC 状态和星座图。
- **讲点**：把"调制识别"和"通信接收"串成闭环：**未知信号 → 识别是什么调制 → 自动选对解调器 → 还原信息**。这正好回答"识别有什么用"的问题。
- **实现**：
  - TX 用 F3 已有的波形生成和 TX DMA 循环发送路径，只是把随机符号换成数据帧；符号速率在 480 kSPS 信道内选择（例如 50 ksym/s）；
  - RX 用信道化捕获（NCO + PFB 输出 480 kSPS），在 PS 上用 NumPy 做定时同步、频偏校正和解调；捕获窗口要覆盖至少 2 个完整帧（必要时加长捕获长度）；
  - 同时支持"识别失败时手动指定调制"的对照。
- **安全**：沿用 B-直插规则和 H2.4 的全部发射约束（arm、40 dB 下限、2.45 GHz、心跳、120 s 上限）。
- **指标**：在 B-直插、无注噪下，100 帧 CRC 通过率 ≥ 95%；从按发送到上屏 ≤ 3 s；三种调制各演示一次；加注噪后能看到 CRC 通过率下降（展示鲁棒性曲线）。
- **提交**：`[H3c] OTA data link: AMC-driven demodulation of text/image frames`

### H3d ADS-B 1090 MHz 航班接收（可选，取决于场地）
- 原理：飞机广播的 1090 MHz 脉冲位置调制报文，2 Mbps 有效码率，**3.84 MSPS 采样足够**。报文只有 120 µs，短快照即可捕获，不依赖连续 DMA（G4d 中连续 DMA 长测失败不影响它）。
- **先探测**（0.5 h，配置 D，天线尽量靠窗）：LO 1090 MHz，采集 10 分钟，用离线脚本检测 8 µs 前导码，统计有效报文（CRC 通过）数。**每分钟 ≥ 5 条有效报文**才继续开发，否则标记"场地不满足"并跳过。
- 开发：PS 解码 DF17（ICAO 地址、航班号、高度、速度、位置 CPR），上位机新增"航班"页：列表 + 简单极坐标图（以开发板为中心）。
- **注意**：答辩场地可能收不到；把探测时录下的报文做成 `.zsr`，现场用回放展示，并明确标注"回放"。只接收和解析公开广播，不涉及隐私。

### H3e FM RDS 电台名（可选）
- 先探测：对 95.8 MHz 等本地电台采集 2 s 连续 IQ（G4d 的 10 秒短测已证明短时连续采集可行），离线检查 57 kHz 副载波和 RDS 同步。国内很多电台不发 RDS，**探测不到就跳过**。
- 能探测到的话：解码 PS（电台名）和 RT（滚动文字），显示在目标卡片和 LCD 上。

### 不做的无线电功能（及原因）
| 功能 | 原因 |
|---|---|
| 解码 WiFi/LTE/GSM 协议内容 | 需要 20 MHz 连续带宽处理（X2 已证明当前 PL 链不行），工作量极大，而且涉及他人通信隐私 |
| FM 发射、非 ISM 频段发射 | 违反无线电管理规定 |
| 433 遥控器信号录制重放 | 有安全和合规风险，不在作品中展示 |
| 干扰或阻塞 | 违法 |
